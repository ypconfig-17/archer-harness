# Desktop Agent 交互规范

本规范是 Desktop UI 的第三层，视觉基础与工作区布局见 desktop-ui-spec.md。Agent 活动优先于静态装饰，界面必须帮助用户判断当前动作、已有结果、是否需要介入、可以检查什么，以及下一步有哪些真实可用的操作。

## 阶段、活动与详情

阶段采用当前执行状态的轻量投影；只有模型或已提交计划明确给出的阶段描述才能显示为任务语义，不根据工具名猜测“正在修复”或“已经验证”。模型显式进度与工具执行活动保持来源区别，内部推理不当作可展示进度摘要。公开过程正文按事实顺序直接展示，原始思考单独折叠；相邻工具调用合并成轻量的可展开记录。模型反馈、用户输入、计划记录与人工交互都会断开工具组，不能按 Turn 把后续活动移动到补充输入之前。主执行流沿正文滚动，不设置包住整轮的大卡片或限高的执行内滚动区。参数、完整结果和错误在中间「活动」页选择对应记录阅读，不在对话内再开第二层详情。未知结果不能显示为确定失败。

## Plan

计划身份、修订与提交边界见 [计划声明与连续执行流](../decisions/task-plan-declarations.md)。每 Turn 同时只有一份当前计划，完成后可以创建下一份，计划不会自动跨 Turn 延续。

主对话简版不为计划生成卡片或段落。创建与结构修订只在历史位置保留一行计划事件，显示标题、步骤数与「模型声明」，点击查看版本与步骤变化；纯进度更新不新增节点。当前 Turn 有声明时，另在输入区上方保留一行计划入口：默认显示标题、完成数与来源，展开后显示全部步骤，当前步骤使用浅强调表面。计划事件在历史中保留；输入区入口只属于当前 Turn，Turn 结束或下一轮没有声明时不显示，也不自动继承上一轮。用户展开后后续声明更新不覆盖该选择。计划阶段不是执行事实，工具成功与 Turn 完成不能替代计划更新；未加载完整历史时不得声称覆盖整个任务。

完整活动中，创建计划和修改标题、阶段结构保留同样的轻量可展开记录，完整修订历史在活动中阅读。历史计划可查看已加载版本，Turn 结束后仍保留。待处理询问、授权与未知结果对账在原操作位置展开；回答后原位折叠，普通询问显示「已回答」，命令显示「已授权本次命令」，执行结果独立表达。取消或未记录回答不能冒充已回答。提交失败保留表单，成功响应后等待事实同步，不重复提交。创建事实尚未加载时明确说明范围并提供当前入口；待处理卡片存在时不重复显示等待阶段提示。

## 运行状态与允许动作

| 权威事实或查询状态 | 界面表达与操作边界 |
| --- | --- |
| 空闲且配置就绪 | 正常输入，允许发送与配置 |
| 准备或执行中 | 显示当前阶段和活动；停止只提交取消请求，不宣称已停止 |
| 命令授权等待 | 明确目标、命令和单次批准范围；只显示 Runtime 已支持的批准和拒绝 |
| 人工回答等待 | 显示实际问题、选项与回答入口，不扩大授权 |
| 操作结果未知 | 提示人工核查；重试需要真实对账与明确选择，不自动重试 |
| 重连或历史未加载 | 显示连接与范围信息，不把暂时无数据解释为任务结束 |
| 完成、失败、取消 | 由结束事实决定；保留本轮历史和结果，后续输入产生新 Turn |

切换会话不停止后台任务；重新进入后由事件及查询投影恢复展示，不恢复前端猜测的执行进度。用户上滚阅读历史时不强制跟随新输出。未实现系统通知或后台提醒的能力不能以假入口或假状态呈现。取消、失败、未知和已确认结果在活动中保持区别。

## 授权、结果与配置

授权界面按目标、关键参数、影响、范围与选择分层；Shell 使用宿主权限，不称为沙箱。当前批准只处理该次请求，不增加“永久允许”等未实现授权。取消与未知结果仍遵循 Runtime 协议。

变更区展示工具确认的历史修改，不推断命令和外部写入，也不冒充当前磁盘文件。普通设置采用行内偏好，高级上下文策略按预设、阶段和参数组织；自定义与内置模板保持真实边界。

本规范约束现有事实投影，不引入新的 Runtime 状态、事件或能力。验证使用投影、计划、授权与恢复行为测试；主题和布局测试不能证明执行语义正确。

## 事件检查的关联边界

事件检查复用已提交事实和已有操作投影，按任务身份、effectId 与原始事件形成阅读层级。默认展开当前加载窗口内最后一组，内部交互默认折叠，显示真实动作、目标与结果；失败、需关注和人工介入筛选自动露出匹配记录。无明确关联的记录不归入相邻调用，同名不同 Provider 或 revision 的能力分开筛选。所有原始编号、顺序、JSON 和加载范围完整保留。

失败筛选包含明确失败事实、工具 isError 及命令非零退出码。“调用返回”不等于“工具成功”；单次失败也不等于整轮失败。人工介入只依据明确授权、人类响应或 ASK_HUMAN 身份，自动对账重试不能算作人工响应。该组织方式不新增执行阶段、Runtime 事件或权限规则。
