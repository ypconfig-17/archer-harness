> 色彩与主题默认值以 [桌面外观与主题系统](../decisions/desktop-theme-system.md) 为准：明暗模式、界面主题与强调色三个维度自由组合，默认深色、Graphite、Graphite Iris，保留有效的本机偏好。本文中的具体色名只描述当前预设，新增界面主题只能改变中性层，新增强调色只能改变强调色 Token。

# 桌面设计系统

检查器的职责、对象身份与事实边界以 [信息架构决策](../decisions/inspector-workspace.md) 为准；当前布局由 [会话工作区与文件检查器](../decisions/conversation-workspace.md) 决定：中间固定「会话 / 活动 / 上下文」三页，右侧工作台阅读任务确认的文件变更与本地 Git 工作区状态。本文中的组件与视图名称用于定位当前视觉实现。

全界面结构与组件使用以 [Desktop UI 设计规范](desktop-ui-spec.md) 为准；本文记录现有区域的具体约束。

## 产品方向与维护边界

Archer 是围绕持续会话工作的桌面应用。首页与对话是主工作区，右侧文件检查器是当前工作的文件辅助详情，设置是主窗口内的独立工作区。采用开放式排版、克制的强调色和稳定的控件密度，避免管理后台式的统计卡片、嵌套容器、通栏表单和重复状态说明。品牌标识保留独立配色，普通界面采用冷灰导航表面、白色阅读层、深灰正文与可切换的强调色。会话选中使用中性浅表面，当前项目只在箭头上提示强调色；强调色还用于主操作、开启状态、焦点与运行中活动。参考 Codex 的窗口比例、信息密度和克制层级，强调色只承担必要交互强调，不大面积铺色。普通按钮、字段与选择器的表面和边界以低比例混入强调色，保证主题在静止状态可见，正文与阅读区仍保持中性。

界面源码、图标、主题与组件属于 `apps/desktop/renderer`，不与 Web 应用共用界面实现。桌面主进程拥有系统菜单、窗口、目录选择、主题同步与后端生命周期；渲染进程通过 `@archer/client` 使用 HTTP/SSE，不实现任务调度。未来独立 Web 界面可以复用 Client 与 Contract，不从桌面目录导入组件、样式或页面。

## 三层设计约束

| 层级 | 唯一入口 | 规则 |
| --- | --- | --- |
| 视觉刻度 | `apps/desktop/renderer/src/ui/theme/design-tokens.css` | 维护字体、间距、控件高度、圆角、主题与状态色；业务组件不新增另一套刻度 |
| 公共结构 | `ui/primitives/Surface.tsx`、`ui/primitives/SegmentedControl.tsx`、`ui/primitives/surfaces.css` | 统一按钮、分段选择、浮层外壳、标题和关闭入口；业务控制动作与关闭策略 |
| 内容布局 | `ui/workspace`、`ui/panels`、`ui/settings`、`ui/navigation` 下的区域样式与业务组件 | 只负责内容排列、宽度与滚动；不重定义公共结构的基础外观 |

全局间距为 4、8、12、16、24、32px。正文块用 16px，普通分组用 24px，容器内边距优先 24px。设置的 `--settings-space-*` 引用同一刻度，不独立维护数值。圆角按用途选小型 6px、控件 8px、浮层 12px；胶囊仅用于短状态或分段选择。标准按钮高度至少 32px，紧凑图标按钮 28px，专用触摸入口 40px，不把所有控件强行放大。

## 页面结构与信息层级

- 首页保持单一会话入口，欢迎信息和输入区共享中心线，不增加概览卡片或管理仪表盘。
- 对话正文保持开放式排版，工具与技术信息按需展开；普通阅读内容不套卡片。
- 中间是会话工作区，固定「会话 / 活动 / 上下文」三个标签，当前标签使用浅强调表面与底部强调线；右侧是独立工作台，阅读工具确认的变更、本地 Git 未提交改动、活动入口与会话已知字段。标签与阅读区分别承担不同层级，不把所有页签压成一排短胶囊。活动页使用可展开的任务与交互分组；上下文页采用扫描布局：标题区切换请求，四格指标读取本次返回值，左栏横向条带表达字符占比、近期 Token 趋势与默认收起的可折叠条目分组，字符占用区块可收起，右栏阅读请求概览、已选上下文与整理事实，两栏可拖动。记录正文使用 UI 字号，ID 与原始数据使用代码字号。
- 设置采用主窗口内页面，包含返回应用、静态搜索、分类导航、固定页头、滚动正文与按需显示的保存操作区。普通设置使用 `SettingRow`，标签、说明和控件固定对齐。提供者用细线分组，模型子项用折叠行；主题与字号使用普通设置行内的 SegmentedControl，策略模板使用带简短说明的单列选择行，选中状态只强调左侧强调线与浅强调底。
- 空态、错误、加载与禁用态在原区域内表达，不使用装饰性大图或重复提示抢夺主任务注意力。成功、警告、危险使用语义状态色，颜色始终配合文字。

## 全界面比例与质感

设计目标是“Codex 的比例与克制，Archer 的色系”。参考维度是主次区域占比、文字与控件的比例、边界强度、浮层深度和信息展开方式，不是逐像素复刻。主会话保持 780px 阅读线；项目导航默认 320px（可拖拽 260–420，本机记忆），文件检查栏默认 400px，已保存宽度限制在 320–420px。主栏头和检查栏头共用 44px 高度。会话栏头以会话名为主，同一行附带工作区位置；打开检查栏时省略重复工作区文字，把空间留给会话名。macOS 的原生窗口按钮保留独立拖动区域，Windows 标题栏与当前主题侧栏同色。

控件分为普通动作 32px、图标动作 28px、触摸入口 40px；按钮内边距必须与行高一起计算，不能仅设置 min-height 后仍被大 padding 撑高。普通按钮、输入框与下拉控件在静止状态就读取 `--control-surface` 与 `--control-border`，悬停读取 `--control-surface-hover`：强调色只混入表面与边界，文字保持正文色，因此未交互的控件也能辨认当前主题，同时不与主按钮的实心强调色竞争。菜单行使用普通控件尺寸，所有动作菜单共用 `@archer/ui` 的 shadcn Base UI `DropdownMenu`，由组件统一负责浮层定位、键盘导航、关闭与焦点返回，不自行实现菜单控件。顶栏的图标尺寸规则只匹配 .header-actions > button，不能用后代选择器把弹出菜单行限制成图标宽度；任务菜单使用 264px 宽度，并将任务和状态时间排在同一行。输入区采用官方 Prompt Input（Input Group + 附件上下文）承担文本框、附件选择、拖拽/粘贴与提交态，外层只负责 12px 圆角、浅边框与轻阴影，空输入的正文最小高度为 28px，多行随内容增长；圆形强调色发送按钮为主要动作；工具栏用紧凑选择器承载模型、推理等级和命令模式。三个选择器共用同一套官方触发器骨架（28px 高、同一内距与字阶、箭头随文字排布而不是绝对定位），模型列表按服务分组、已选模型只显示名称；推理等级以“思考”标注，不重复模型图标；命令选择按实际文字宽度布局，浮层固定 264px 容纳两行说明。

下拉选择使用 shadcn/ui Base UI `Select`（`SelectTrigger` / `SelectValue` / `SelectContent` / `SelectItem`），单选命令模式使用 `DropdownMenu` + `DropdownMenuRadioGroup`；浮层、选中行与勾选由包内 `cn-select-*`、`cn-dropdown-menu-*` 规则统一绘制，选中行使用浅强调底与强调勾选，长选项在控件宽度内单行省略。仅仍依赖 base-select 原生展开行为的密集表单使用 `NativeSelect`，业务不直接书写裸 `select`。复选框、单选框与滑块使用强调色作为系统强调色，文件选择按钮沿用公共按钮表面，数字步进按钮隐藏。macOS 菜单栏、原生右键菜单与标题栏框架仍由系统绘制，只跟随明暗。

阴影只表达深度：输入区使用轻阴影，菜单与跳转入口使用浮层阴影，模态窗口使用窗口阴影。对话中的计划属于文档流内容，不使用浮层阴影或定位覆盖。普通内容分组没有阴影；背景、状态边框、圆角与阴影均取 design tokens。危险、警告和成功色与蓝色操作强调分开，不把未知结果显示成失败或成功。

会话、项目、模型和策略配置复用设置窗口的导航、页头、正文和保存区；列表动作采用轻量文字按钮，避免为每条记录排列一组重边框按钮。条件树的左侧缩进与边线表达逻辑嵌套，不能为了视觉扁平化丢掉 ANY / ALL 的分组意义。

审批与人工回答使用同一个交互表面，命令、说明、选项与动作纵向排列。选项采用浅强调选中底，确认按钮采用强调色主动作，拒绝和取消保持次要层级。未知结果对账的核查勾选、原因输入和明确重试条件保持完整。上下文配置删除使用应用内 ConfirmDialog，默认聚焦取消，Esc 只退出当前确认，删除只发生在显式确认后。

代码、终端和 Diff 共用代码字号、低反差代码底与小边框；代码栏头、复制动作与输出区遵循统一控件刻度。Diff 的正负号、颜色和文字并用，不能只靠颜色区分。历史详情与当前运行流复用相同记录结构，事实顺序、折叠和未加载范围不受视觉调整影响。

全界面检查范围与具体取舍见 [桌面视觉语言](../decisions/desktop-visual-language.md)。构建与静态检查不能替代真实界面的观感验收。

## 设置与详情的视觉结构

设置工作区替换主导航与检查器的可见区域，分类导航宽 220px，正文宽 800px，内容水平留白 28px。标题使用区块字号，说明使用辅助字号，页头不增加通栏分隔线；分类分组仅用短间距与细线区分，不显示后台式分类大标题。「返回应用」是动作入口，使用普通控件表面；分类导航行保持无底色，选中时使用浅强调表面与左侧强调线。分类导航复用包内 Sidebar 菜单原语，行高、字阶与选中表达由设置样式按规范覆盖，键盘焦点使用行内描边，不越出导航列。当前配置的保存范围放在导航底部，保存按钮与错误反馈仍位于编辑器自己的固定操作区。窄窗口使用分类选择器，正文保持独立滚动。

外观页包含外观模式、界面主题、强调色、文字大小与对话五个分组。外观模式使用行内分段选择（浅色、深色、跟随系统），界面主题使用四张缩略选择卡（显示窗口、阅读面、边界三层色块、名称与中文说明），强调色使用色点、名称、中文说明与十六进制值的单选行并支持自定义输入，文字大小与代码选项继续使用设置行。页面底部是可折叠的「主页实时预览」，使用真实导航、Agent 卡片、按钮、选中条目、运行状态、输入框和状态标签，全部读取当前语义 Token。选择通过 aria-radio / aria-checked 表达，切换立即生效并持久化；预览不接收交互，也不假装展示尚未应用的字号。

右侧工作台的窗口结构由 Workbench 维护，样式位于 ui/panels/inspector.css；审阅只承载工具回执确认的文件变更，工作区只读本地 Git 的 HEAD 与当前文件差异并标注为磁盘状态，活动与会话概览只读取已提交事实，不提供请求快照、能力来源或第二套执行状态。中间的检查页与页签、工具栏共用同一条左边界，不再在页面内再居中出窄栏。活动页的事件列表以任务分组与紧凑交互行组织，单条记录详情展示结构化字段与完整原始 JSON；能力来源回到设置的全局来源页，不在中间另开阅读区。

普通弹窗标题使用区块字号，关闭按钮固定在右上方；标题与正文靠间距分开，不使用重复的重分隔线。设置、调用记录与确认框共享同一遮罩、表面与圆角，具体滚动和关闭策略仍由业务控制。

## 公共组件与浮层契约

`Button` 采用 shadcn/ui Base UI 官方源码与变体：variant 接受 default、secondary、outline、ghost、destructive、link，size 接受 xs、sm、default、lg 与四种 icon 尺寸；默认 `type="button"`，表单提交显式指定 submit。一个操作区通常只有一个 default 主操作。secondary 使用中性轻表面，outline 使用明确边界，ghost 只保留透明的轻量入口；default 使用实心强调填充，destructive 使用危险色。颜色经包内 Tailwind 桥接映射到 Archer 语义 Token，圆角、字号和密度使用 `--radius-control`、文字大小与间距刻度。普通按钮、设置保存和历史管理动作共享同一套尺寸与状态，不再各自定义圆角、字体或背景。设置与弹窗中的输入、下拉触发器同样取控件表面，分段选择的选中项使用浅强调底。只读行、列表行与普通消息保持中性表面。业务中不出现未套用公共按钮类的裸 `<button>`；紧凑纯图标操作保留独立语义与可访问名称，但表面与悬停仍取控件 Token。

所有弹窗通过 `@archer/ui` 的 `Dialog`（内部原生 `<dialog>` 与 `ui-dialog` 表面）渲染，并使用 `size` 声明阅读宽度：small 为 460px，medium 为 560px，large 为 820px；设置使用专属 settings 布局宽度。浮层共用 12px 圆角、边框、主题表面、窗口阴影和同一遮罩，不分别添加背景模糊。尺寸受可用窗口宽高约束。

有关闭入口的记录和流程窗口使用 `DialogHeader`，标题、说明和关闭按钮保持同一对齐。确认框采用紧凑正文与右对齐操作区；设置保留分类导航和草稿检查。浮层只统一外观，不接管保存、删除、取消或未知结果的业务语义：保存中是否可关闭、Esc 如何处理、关闭是否丢弃草稿由调用方显式决定；原生 dialog 保持模态焦点约束。危险动作仍需原有确认，不因统一组件自动执行。

## 开发与验证

`pnpm dev:desktop` 构建后端与主进程，由桌面启动脚本启动独立 Vite 界面并等待监听就绪，再启动 Electron；应用退出时关闭开发服务器。`pnpm build` 输出主进程到 `apps/desktop/dist`，界面到 `apps/desktop/dist/renderer`，界面构建不能清空主进程产物。`pnpm start:desktop` 加载桌面自身的 index.html。渲染进程的服务地址由 preload 注入，管理令牌由主进程附加，不通过前端环境变量配置。

验证命令为 `pnpm build`、`pnpm -r typecheck`、`pnpm test`、`pnpm lint`。界面行为测试位于 `tests/desktop/renderer`，主进程测试位于 `tests/desktop`。静态与行为检查只能验证编译、资源引用和交互契约，不能据此声明实际视觉效果已经验收。视觉验收需覆盖首页、长对话、中间活动页、右侧工作台、设置长表单、确认框与记录框，以及浅深主题和窗口缩放；是否进行实际界面检查由任务要求决定。

## 字体与图标

字体的唯一维护入口是 `apps/desktop/renderer/src/ui/theme/design-tokens.css`：字体族、字重、语义字号、行高、三档偏好和 Tailwind 字体映射均在此定义。`foundation.css` 与 `@archer/ui` 不再重复定义字体映射；组件样式只引用 Token、继承字体或使用已桥接的工具类。Tailwind 默认字号表被清空并映射到桌面刻度：xs 为辅助、sm 为 UI、base 为弹窗标题、lg / xl 为区块标题、2xl 至 9xl 为页面标题，避免第三方组件引入额外大字号。粗体工具类保持既有 semibold 映射。

Markdown 桥接只负责为正文、标题和代码选择语义角色，正文行高直接读取当前字号档位的行高与字号比例。官方 `typeset.css` 保留原版；组件目录中隔离的官方对照页保留官方字阶用于对照，不属于产品字体规则。禁止在自有产品 CSS 中新增独立字体常量或另设 Tailwind 字体映射。

验证运行 `pnpm exec vitest run tests/desktop/renderer/typography-tokens.test.ts` 和桌面生产构建；前者扫描桌面与共享 UI 的 CSS，防止独立字体常量和重复字体桥接回流。视觉验收在三档偏好下检查导航、设置、菜单、弹窗、正文标题、表格与代码；明暗模式不改变字体刻度。

主题配色、对比文字、焦点光圈与视觉刻度统一维护在 `apps/desktop/renderer/src/ui/theme/design-tokens.css`，由 `index.css` 导入。界面主题按明暗定义中性层，强调色预设只覆盖 `--accent-default`、`--accent-text` 与 `--accent-foreground`；自定义强调色由 theme.ts 推导可读的文字与前景色，以内联变量覆盖同一组角色。字体使用系统无衬线字体，代码使用系统等宽字体，不依赖网络字体。字号、字重和行高按用途一起引用，不在组件中定义独立的像素字体。

用户可以在外观设置选择小、中、大三档全局字号；中档使用下表基准，小档和大档只覆盖语义字号与对应行高。图标、品牌图形、内容宽度和控件点击区域不随字号缩放，避免改变图标体系或降低可操作性。偏好保存在当前设备，并通过根节点 `data-font-size` 统一作用于所有引用语义 token 的界面。

| 用途 | CSS 简写变量 | 字号 / 字重 / 行高 |
| --- | --- | --- |
| 品牌 | `--type-brand` | 16px / 600 / 24px |
| 页面标题 | `--type-title` | 24px / 600 / 32px |
| 区块标题 | `--type-section` | 18px / 600 / 24px |
| 文件夹名称 | `--type-folder` | 14px / 500 / 20px |
| 会话列表、按钮、输入 | `--type-ui` | 14px / 400 / 20px |
| 对话正文 | `--type-body` | 14px / 400 / 24px |
| 辅助信息 | `--type-caption` | 12px / 400 / 18px |
| 工具输出、代码 | `--type-code` | 12px / 400 / 18px |

组件可使用 `font: var(--type-ui)`；需要保留继承字体时分别引用该用途的 `--size-*`、`--line-*` 与 `--weight-*`。正文与列表保持常规字重，目录与选中项使用 medium，标题使用 semibold。左侧项目文件夹行统一使用 `--type-folder`（默认 14px / 20px、500），不额外放大一级树节点；会话行默认与选中均使用 400，选中通过底色与文字颜色表达，避免切换时文字粗细变化。目录与会话通过缩进和适度字重区分层级。Tailwind 的字体族与字重也指向这些变量。

图标统一使用开源 Phosphor React 的 regular 轮廓，通过 `ui/primitives/Icon.tsx` 使用语义名称，按单个图标导入。新对话使用 PencilSimpleLine，文件夹使用 FolderOpen，终端使用 TerminalWindow；不混用其它图标库或手绘功能图标。Archer 品牌标识是独立的品牌图形，使用 A 字形与向右上方延伸的弧线箭头，A 从蓝紫渐变到浅青蓝，箭头使用紫色，不添加立体光泽。`apps/desktop/renderer/public/archer-mark.svg` 用于侧栏与欢迎页，保持原始配色，不使用单色遮罩；`favicon.svg` 使用相同图形与白色圆角底板。桌面应用的 PNG、ICO 与 ICNS 图标保持相同造型与配色，并按 macOS 图标网格排版：1024 画布上的圆角方块为 824，四周各留 100px 透明边距，圆角半径随方块等比缩放（约 185）。Dock 给每个应用的格位相同，方块占满画布会让图标在 Dock 中比其他应用明显偏大；`assets/icon.png` 由主进程 `app.dock.setIcon` 直接渲染，不会被系统补边距。

`Icon` 的 size 只接受 xs / sm / md / lg，分别对应全局 12 / 14 / 16 / 22px，默认 md。不在调用位置写像素尺寸或覆盖笔画；图文间距引用 `--icon-text-gap`，侧栏缩进引用 `--nav-indent`。图标装饰性隐藏，按钮由可见文字或 aria-label 提供名称。

侧栏目录与会话行高 30px，工作区组间距为 0；子会话沿固定图标与文字列缩进。新对话使用轻量文字入口与笔形图标，目录使用打开的文件夹轮廓。会话行尾只显示排队数量，不写相对时间或其它活动描述；目录行在有任务运行时显示运行数量。行尾列宽独立于标题省略，不使用推断结果。

## 回复正文排版

对话内容最大宽度使用 `--conversation-width`（780px），用户消息、任务信息、执行摘要与输入区共用内容对齐线；窄屏按可用宽度收缩。正文保持 14px / 24px，不随容器宽度放大。

Markdown 块间距由容器统一提供，避免段落与列表的 margin 重置覆盖间距：普通块之间 12px，章节标题前额外增加 12px，标题与后文之间 8px。标题在任何位置均保留对应级别的字体。顶层列表项之间 12px，嵌套列表项之间 6px，列表缩进 22px；刻度统一维护在 design tokens 中。

行内代码使用低对比底色、小内边距和无边框样式，允许长内容换行。独立代码块保留语言提示、复制按钮、可选高亮和行号。代码高亮由 shiki 提供，令牌颜色通过 `--shiki-foreground` 与 `--shiki-token-*` 变量维护在 design tokens 中，随浅深主题切换；非预热语言在语法懒加载完成后补充高亮。回复使用 CommonMark 与 GFM 语义，原始 HTML 以字面转义文本出现，不进入渲染树；链接只打开 HTTP(S) 地址；HTTPS 远程图片先显示说明，由用户主动加载。渲染器不根据字符长度转换行内代码。任务信息与折叠执行摘要使用辅助字号和紧凑间距，异常提示保持可见。

正式回复使用 KaTeX 排版行内与块级数学公式。`mermaid` 围栏在严格安全模式下生成图表，图表可查看并复制原始源码；语法错误或超过规模限制时回退为带说明的代码块。流式预览不排版数学或生成 Mermaid，待内容正式提交后统一渲染，未提交的中断内容始终保持临时预览语义。

## 对话任务洞察

当前计划只在输入区上方显示一行标题与声明步骤进度，点击展开步骤，不进入对话段落或累计摘要；完整计划修订在活动中阅读。对话里的累计摘要每 Turn 一行，显示调用数、片段状态与已知耗时，展开后回到调用列表，不根据任务结束或工具成功自动勾选计划。文件修改通过对话中的轻量入口打开右侧文件检查器，入口显示工具确认的修改 / 新增 / 未知文件数量；最近推理上下文通过中间「上下文」标签查看。修改仅汇总已确认结果中的 fileChange，相同路径只有前后内容连续时合并，否则保留独立片段；命令及外部写入不计入文件统计，历史 diff 不代表文件当前内容。任务开头未加载时明确标注信息范围。

上下文页默认显示最近一次已提交 INFER 请求，可用选择器或前后按钮切换已加载的请求快照。输入 Token、缓存 Token 与消息投影来自该次推理返回事实；横向条带按请求中的正文字符数计算会话消息、工具结果、工具声明、系统指令与推理参考的占比，标签明确写「字符」，不换算成 Token，也不在缺少容量时显示百分比。Token 趋势用同一组语义色画堆叠柱：柱高是已提交的输入 Token，分段只按字符占比分摊并在脚注说明；总量折线在缺失用量的请求处断开，当前请求带强调色描边与数值徽标，首尾请求的徽标向内对齐，窗口较长时按步长抽稀横轴序号。当前值与较上次变化收在图表上方一行，图表占满左栏宽度；字符占用区块可用标题折叠，默认展开。消息按角色分组，工具声明与参考整理各自成组，分组默认全部收起、只显示标题与计数，搜索命中或条带跳转时展开，切换请求后回到收起；搜索、类别筛选、条带跳转与折叠只改变条目视图。准备能力的实际返回内容以执行结果为准。

模型过程文字与 provider 实际返回的 reasoning 按推理和工具发生顺序展示，不另收进“过程说明”；reasoning 保留可展开正文与摘要，未返回时不虚构思考内容。最近工具的收起范围同时保留其相邻模型过程。当前阶段状态显示在列表折叠区外，折叠历史不会遮住实时状态。任务未完成时使用“模型正在处理 / 思考 / 输出”，只有已提交 turn.completed 后才展示最终答复及完成统计。

## 工作台布局与配色

浅色外观使用白色阅读面、冷灰导航与深灰正文，主操作使用当前强调色，设置与检查栏的选择使用浅强调表面。正文维持 14px / 24px，辅助信息为 12px / 18px；不根据设计参考图整体缩放字体。深色外观沿用相同信息层级，颜色通过主题变量切换。

侧栏默认 320px 承载品牌、新对话、搜索与按工作目录分组的对话历史；macOS 下使用同族半透明表面透出系统毛玻璃，顶部留出系统标题栏拖动区。底部只保留设置、异常历史入口与服务状态，工作区选择使用项目标题旁的文件夹入口。连接状态来自实际服务，不展示虚构的账户身份。收起后保留 56px 图标列，展开入口位于工作区左上角；窄屏使用抽屉导航。

主对话保留用户消息、Archer 署名、公开反馈、工具调用、授权交互和最终答复。用户消息采用靠右、随内容宽度收缩的浅蓝气泡，时间和复制入口放在气泡下方，不显示头像与重复署名；Archer 组头在已加载 Turn 开始时附辅助字号时间，开始事实未加载时不补造；公开反馈文本开始一个自然段落，连续工具以无底色、无外框的缩进短行附在其后，已结束调用折叠、运行中与异常调用保持可见；任务结束后收在答复底部的辅助信息行，展开后查看参数与输出；成功、失败、未知和取消状态沿用已提交事实的投影。

右侧工作台默认宽度 400px，可在 320–420px 范围内拖动或用方向键调整，并支持关闭和最大化；它的审阅入口只阅读当前任务工具确认的文件变更，工作区入口只读本地 Git 未提交改动、标注「不代表任务记录」，不提供视图添加或页签关闭。中间固定「会话 / 活动 / 上下文」三个标签：会话承载主对话，活动承载已提交事件的筛选、分组列表与单条记录详情，上下文承载已提交 INFER 请求的字符组成、Token 趋势、消息、工具声明、参考与整理事实；活动页不提供请求上下文、调用详情、会话概览或能力来源二级视图。工作台首页以入口卡打开审阅、工作区、活动与会话概览，会话概览只列已提交的已知字段，不推算进度。

设置是主窗口内的工作区，包含返回应用与左侧分类导航：通用设置、外观与主题、快捷键、模型设置、上下文、能力来源、对话记录、工作区、关于 Archer。通用设置包含默认工作区、默认模型、语言、默认文件访问范围、启动页面，以及对话记录保存、代码高亮和行号显示；语言当前只提供简体中文。对话记录以同样的行式布局列出全部会话，每行展示标题、工作区、创建时间与运行状态，删除需在行内二次确认；删除保留已提交日志，运行中的会话不可删除。工作区汇总导航记录与会话工作目录，行内提供新对话、移出/恢复导航和移除无会话记录，移除只影响本机导航。通用偏好保存在本机，模型服务配置仍显式保存；文件访问与命令授权分别表达。关于页展示版本、推理方式、运行平台与服务地址。设置不提供账号与成员、独立工具注册表或记忆配置页：文件范围与命令授权分别表达，工具由 Tool 和 Skill 契约投影，记忆模块由宿主显式加载。工作目录选择使用桌面壳的系统目录选择器。

活动视图投影已提交事件，默认按任务和交互分组，记录行保留时间、摘要与原始序号；工具栏只承载筛选与范围，不重复一级导航。选中记录后在列表下方阅读结构化字段与完整原始 JSON，窄容器下详情替代列表并通过返回回到记录列表。筛选不改变事实顺序，新事件到达不把旧选择套到新记录；没有记录时显示空态。

用户消息在气泡下方显示发生时间，Archer 最终答复显示署名；结束时间、耗时与用量收进默认关闭的运行详情；Agent 正文使用无外框、无卡片底色的开放排版。模型过程摘要与工具调用按原始顺序放入同一个列表，每项一行，点击展开详情；列表最大高度 280px 且不超过窗口高度 40%，超出后内部滚动，用户上滚阅读时暂停自动跟随；任务结束后收在本轮答复底部的一行入口中。工具状态同时提供文字与颜色，已完成调用保留可见状态。当前阶段标题和阶段状态始终位于列表折叠区之外。命令审批卡片优先展示目标能力与实际命令，原始请求和权限说明按需展开；审批、拒绝与结果未知处理沿用原有 Runtime 协议。

每个 Turn 的累计摘要以单行入口呈现，默认收起，用户手动切换后保持该选择。公开反馈与连续工具组成自然段落，摘要不替代段落；展开摘要后按真实顺序列出本轮调用，并提供「查看全部活动」，不生成浮层或覆盖主对话。计划只在输入区显示一行入口，不进入摘要，不按任务结束自动改变步骤状态。没有工具调用时不生成零调用摘要；工具参数与结果在单次操作详情中阅读。任务结束后摘要保留，历史调用按需打开，文件修改通过答复底部入口在右侧阅读。

对话中的工具行不逐条添加圆角卡片和状态色块；连续完成的调用折叠为一行，失败、未知和运行中调用保持单行可见。Shell 只显示一行省略的命令预览，完整命令、目录与输出在详情中查看。原始推理不进入主对话，只在完整活动中的推理入口阅读。工具列表折叠行提供调用数量、读取 / 修改 / 执行分类计数与需关注数量，不重复展示“正在生成回复”。

命令审批模式按服务和 Agent 保存为本机默认选择，新建 Agent 时承接创建任务中实际选择的模式；后续发送仍显式携带 commandMode，不改变 Runtime 的单次任务授权边界。运行中修改授权成功后才更新默认选择。文件访问配置在右侧工作台的「会话概览」阅读，输入工具栏展示模型、推理等级与命令模式。已结束任务的工具历史通过答复下方的调用数量按钮打开居中弹窗。弹窗复用进行时的无卡片紧凑列表，完整记录按顺序展示，内部滚动，每项点击展开详情；不撑开正文，支持关闭按钮、Esc 与点击遮罩关闭。

执行过程中在阶段状态下方展示一个「N 个文件变更」摘要卡：顶栏是折叠开关，文件图标开头，右侧以辅色列出已确认的修改 / 新增 / 未知构成，行尾箭头随展开状态旋转，默认折叠。展开后是紧凑文件列表，每行显示文件图标、文件名、可省略的目录、状态与进入箭头；点击文件直接打开右侧「变更」工作区并定位到该文件。文件过多时只让列表内部滚动并限制高度，不撑开对话；完整路径在行的悬浮提示中阅读，不把路径拆成多行。卡片只汇总工具已确认的修改，不在正文内展开 Diff。点击文件后打开的右侧「变更」工作区：左侧显示本轮文件目录树和筛选，右侧阅读选中文件的历史内容；顶部为路径与差异、源码、Markdown 预览切换。结束后答复下方保留同一入口；从历史调用弹窗打开时先关闭弹窗。相同路径只计一个文件，连续修改合并后统计，不连续修改分段累计。缺少原文时标记行数未知，不把已写入内容的行数当作净新增；工具回执带有 `revisionBefore` 时可确认是修改，但仍不声称原文内容或行数；Shell 与外部写入不从命令文本推断文件变化。结束后摘要随工具历史保留。

主会话使用「320px 项目导航 + 中间会话工作区 + 右侧文件检查器」的三栏布局：文件检查栏跨越主对话标题与内容区域的全部高度，拥有自己的栏头、滚动区和分隔线；主对话标题不会横跨右栏。窄屏切换为独立浮层，最大化覆盖主工作区。品牌标识尺寸使用独立的 --brand-mark-size（24px），不受功能图标 lg 尺寸限制；文件检查器标题使用 sm 图标。输入区不展示会话权限入口或固定的命令边界说明，文件访问选项在右侧工作台的会话概览中阅读。

首页使用通用欢迎文案“欢迎使用 Archer”，不限定开发任务，不提供快捷任务卡片。当前工作区紧贴输入框上方展示。欢迎标题、简短说明与前置品牌图标同一行居中；新对话按钮使用浅色选中底降低视觉重量。

主对话的工具短行只呈现动作、目标、状态与已提交耗时，不承担跳转；完整参数、命令、cwd、结果与退出信息在中央「活动」页对应记录中阅读。已结束任务的调用历史仍通过答复下方的调用数量按钮打开居中弹窗，弹窗按原序展示同一组短行。答复底部默认只显示终态、工具确认的文件变更构成与需关注项，需关注项作为整体换行，不在图标与计数之间断开；整轮耗时、调用次数、模型、推理次数、累计 Token 与缓存明细收进默认关闭的“执行详情”。整轮耗时包含等待，Token 标注本轮累计输入输出，不将累计量当作当前上下文占用；未返回用量时明确说明，不补成零。执行详情使用 `@archer/ui` 的 `InteractionRecord`：关闭态是一行记录入口，右侧显示推理次数；展开后按「执行」「用量」分组事实。模型名用代码字体，数字使用等宽数位。上下文整理不进入答复，只在执行中显示一行阶段状态。

## 窄屏可读性与键盘导航

停止任务只提交取消请求，等待确认期间不允许继续补充原任务；输入方式转为排队下一任务，暂停队列中的新输入不会自动执行。队列恢复、清空和消息提交互斥操作，停止确认期间不可恢复队列，隔离或 blocked 状态不提供队列操作；最终准入仍由 Runtime 的已提交事实决定。

输入框不添加队列状态、授权边界等常驻说明，保留简短占位文案与发送方式选择。空队列不展示队列面板或独立恢复按钮；空暂停队列的发送按钮通过悬停文案和无障碍名称标注“发送并恢复队列”。首次发送先确认文件授权准备成功，再恢复空队列并提交输入；任一步失败不继续发送。有积压任务时发送按钮表示“排队下一任务”，用户可清空积压后发送新任务，或显式恢复队列继续处理。清空队列不会自动解除暂停。

队列采用输入框上方的紧凑列表，标题、待处理总数、暂停状态与恢复/清空操作位于同一栏；窄屏允许栏头换行，操作保留触摸区域。列表使用顺序号而非内部 inputId，补充输入单独标记并计入总数，不展示冗余的空队列说明。列表高度有界，长内容自动换行、超出内部滚动，不挤走正文与输入框。配色复用浅色辅助背景、细分隔线和主题语义色，字号、间距与图标尺寸引用集中式设计 token；执行、暂停和请求重试语义保持不变。

消息提交结果未知时保留原请求、内容和发送方式，重试只提交同一 requestId，不重复恢复队列或配置授权，避免覆盖随后提交的停止操作。队列操作在未确认消息解决前禁用，停止当前任务仍可使用。相关行为通过 `pnpm exec vitest run tests/desktop/renderer/message-submission.test.ts tests/desktop/renderer/queue-panel.test.ts tests/desktop/renderer/submissions.test.ts` 验证；页面检查应覆盖停止确认、空暂停队列、有积压的暂停队列及恢复失败后草稿保留。

设置中的下拉选项在窄屏独占一行，说明文字使用整行宽度；开关仍与标签并排。主要触摸操作使用 40px 点击区域，窄窗口设置分类使用选择器并保留返回应用入口。关闭的移动导航不可获得焦点，导航入口通过 aria-expanded 表达展开状态；Esc 关闭导航并将焦点返回入口，有弹窗时优先由弹窗处理。工作区选择保留可见焦点光圈；组合搜索只改变外层描边颜色，不叠加第二层光圈。辅助信息颜色保持可读对比，长工作目录允许换行。

模型旁的推理等级选择使用中文显示，选项来自该模型的实际能力；默认值和本机偏好按模型独立管理。模型设置提供推理能力与默认推理等级，当前推理的实际等级在上下文面板展示。选择只影响后续提交，不修改运行中任务。

## 能力提供者

设置和检查面板共用按 Provider 来源组织的能力视图。概览展示当前 Archer 的提供者数和能力数，搜索覆盖来源 ID、能力 ID、用途与契约类型。每个来源先展示贡献的类型与能力数量；能力行呈现名称、中文用途以及工具的读取、写入、宿主命令和人工交互声明，展开后只看能力 ID、契约和来源 revision。用途取自工具作者声明给宿主的 summary，其他契约使用自身的 description；工具面向模型的说明、输入 Schema 与原始元数据不进入界面。来源 identity 独立折叠，保留作者声明的原始内容，不将 revision 解释成代码签名。

已接入只表示宿主提供的声明，不表示运行健康或执行授权。界面明确提示各会话共享能力，文件范围与命令授权按会话及任务落实；不提供动态安装、启停或虚构的健康状态。加载、读取失败、未接入及搜索无结果分别展示对应反馈，失败时可重试。

### 会话操作与异常历史记录

侧栏会话行的 `…` 与导航按钮同级，提供重命名和删除；悬停、键盘聚焦、选中时显示，触屏常显。
删除确认在侧栏、会话页右上角和设置的对话记录中保持一致，明确说明移除会话、保留事件日志和工作区文件。
读取状态失败、正在读取、任务运行或有排队输入时不允许从侧栏删除；服务端继续负责最终准入。
工作区菜单的“从侧栏隐藏”只改变本机导航，保留目录与会话。

“历史会话无法恢复”是启动校验诊断，与会话内的模型报错区分。点击提示或设置中的“管理异常历史记录”打开明细。
明细显示会话标识与失败原因，不从未通过校验的日志猜测标题。提供导出原始记录、移出加载范围和全部移出加载范围。
移出前明确确认数量与保留位置，处理中禁用重复操作及关闭；部分失败后刷新实际剩余记录并展示错误。
空列表明确显示没有待处理记录。所有异常处理均不触发模型调用、外部操作重试或任务结果修改。

验证方式：用空闲、运行中、带队列和读取失败的会话检查三个删除入口；取消确认应保持会话不变。
删除当前会话应返回新对话，删除其他会话应保持当前页面。用不兼容 JSONL 检查诊断、导出与移出，重启后不应再次加载已隔离文件。

## 上下文压缩等待与记录

对话中的执行区域直接投影已提交的 `inference.requested`、`inference.responded` 和 `context.compacted`：摘要请求提交后显示“正在压缩上下文…”，收到响应但没有采用事实时显示“正在核验上下文摘要…”，采用后显示“上下文已整理，正在继续任务…”。摘要未采用、普通请求已提交时显示“正在使用原始上下文继续任务…”，并注明该请求可能使用工具结果节选。响应或 token 用量不能单独证明摘要已采用。

等待提示不展示摘要正文、完成百分比或预计剩余时间。停止操作沿用任务已有入口，点击后等待确认；会话隔离或阻塞时显示暂停提示，不继续呈现加载动画。请求保留所属 Effect 的执行 attempt，恢复后的新 attempt 不继承旧请求的等待状态；刷新和 SSE 重连使用同一事件投影，无新增进度接口或持久化状态。

执行摘要只标识调用数量、片段状态与已知耗时，当前阶段只在列表外的底部显示一次。压缩、核验、继续、暂停和停止均使用一行辅助文字与状态图标，不使用蓝底卡片、侧边强调线或常驻长说明；失败与停止本身也只占正文层级，不使用输入框式错误卡片。补充说明通过悬停可查；压缩失败明确使用错误文字与图标，临时中断优先显示等待确认，不继续转圈。

摘要请求与整理结果不在答复中留存：执行中只在执行列表外保留一处“正在压缩／正在核验”状态，任务结束后撤下，不在每次 INFER 之间重复插入记录。逐请求的响应、采用状态与 `contextPlan` 估算在「上下文」页签按推理记录阅读；已采用以整理事实为准，未采用不从请求输入量推算收益，取消或失败且没有最终估算时明确显示未记录。原始模型过程和工具调用仍按事实顺序呈现，视觉合并不合并或改写日志。

验证入口：`tests/desktop/renderer/context-status.test.ts` 覆盖提交、核验、采用、原文回退、失败、中断、停止、暂停、attempt 恢复，以及结束后不保留整理记录；`tests/desktop/renderer/conversation.test.ts`、`tests/desktop/renderer/process-presentation.test.ts` 覆盖既有事件顺序与任务归属。执行 `pnpm test`、`pnpm typecheck`、`pnpm lint` 验证。

## 任务余额不足提示

任务失败区和 Markdown 导出将明确的 `insufficient_balance_error` 或 `Insufficient Balance` 上游错误显示为“模型服务余额不足，请充值或切换模型后重试。”。支持带 `402:` 前缀的 JSON 和普通文本，以及嵌套 `error` 对象；不单凭 HTTP 402 或 `invalid_request_error` 判定余额不足，未识别的错误保留原文。

转换仅作用于展示，不改变已提交事实、失败状态或重试策略；JSON 导出保留原始错误及请求标识，供排查使用。验证：`tests/desktop/renderer/task-error.test.ts` 覆盖原始报错、嵌套错误、文本和非余额错误。

## 阅读界面的结构检查

答复与输入区是会话界面的主要内容。运行统计、计划和模型选择属于辅助层级，不应形成另一条常驻数据仪表盘。公开反馈与连续工具构成自然段落，累计摘要保持单行且无卡片底面；计划只在输入区保留一行入口，声明来源与完整步骤在展开内容中，完整修订历史通过「查看全部活动」进入活动视图。

`tests/desktop/renderer/reading-layout.test.ts` 检查顶栏尺寸样式的作用域，防止图标宽度误伤嵌套菜单；同时检查运行详情默认关闭、统计与模型信息仍可查，以及缺失用量仍显示未知。该检查不运行浏览器，不代表菜单实际像素布局或主观质感已经验收。

## 检查工作区的交互契约

会话工作区的「会话 / 活动 / 上下文」三个标签通过 aria-controls / aria-labelledby 关联；左右方向键、Home 和 End 切换并聚焦标签，切换不重建对话滚动或待提交输入。工作台每次只显示一个阅读对象：审阅、工作区、活动或会话概览，不提供标签添加、页签关闭或横向滚动；收起工作台与最大化分开，关闭后焦点返回打开入口。保留已保存的工作台开关与宽度偏好，不重置用户布局。

会话概览默认展开会话与工作区，其余分组按需打开。文件访问沿用原授权和准入逻辑，分组折叠不改变配置。会话概览只投影已提交的事实字段，不读取当前文件，也不新增文件浏览能力。实现取舍见 [检查工作区](../decisions/inspector-workspace.md)。

验证入口为 `tests/desktop/renderer/workbench.test.ts`、`event-panel.test.ts`、`event-navigation.test.ts` 与 `changes-panel.test.ts`：覆盖工作台入口与返回、工作区视图的文件阅读布局、活动筛选与记录选择、标签与内容的可访问关联，以及文件变更的已确认边界；Git 读取本身由 `tests/archer/workspace-git.test.ts` 覆盖。键盘焦点移动、容器宽度切换和视觉质感仍需运行界面验收，静态检查不替代这一过程。

## 已确认的工作区视觉基准

[桌面四态母版](../design/desktop-baseline.html)约束四栏比例、结果摘要、执行行、检查器和输入区的层级。它是设计参考，不是运行截图；界面使用真实品牌资源与事实，不照搬示例文件、时间和调用数据。文件检查器默认 400px，已保存宽度在 320–420px 内保留。执行记录使用统一 40px 控件节奏，左侧表达动作，右侧收口结果与耗时。

变更区仅保存任务身份和本机文件选择，随已提交事实重新投影。切换会话或任务不复用其他任务的选择；文件筛选不强行改变当前阅读内容；对话入口只汇总已确认的修改 / 新增 / 未知数量。没有修改时提供明确空态，长路径截断并保留完整提示，列表与阅读区独立滚动。连续修改合并，不连续片段分别标记；缺少原文不推断净新增行数。Diff 默认保留修改邻近上下文并限制首次行数，完整内容按需展开。

验证使用桌面构建、Lint 与 renderer 单元及服务端渲染测试，覆盖未知原文、未完成结果、片段连续性、变更入口和 Diff 行号。按项目要求不执行浏览器测试；这些检查不等同于实际窗口的视觉验收。

### 侧栏目录对齐

文件夹行使用文件夹图标与标题两列，不再占用独立箭头列；「项目」标题、文件夹图标与会话图标共用左侧一条竖线，项目名与会话标题共用文字起点。点击分组行展开或收起，展开和悬停不移动文字。子会话图标对齐文件夹图标；新对话和展开更多也沿用文字起点。当前、运行和暂停状态在同一图标列显示状态点，不在文字尾部追加漂移的标记。长标题在独立文字列截断，行尾菜单以浮层出现且不占文字列，选中背景覆盖整行。缩进刻度集中在 design-tokens.css，折叠行为、会话选择和工作区数据保持原有语义。

### 文件工作区布局

文件展示采用左目录、右阅读的结构。目录列随文件工作区宽度收缩，上限 240px，最小保留文件名前缀；单子目录压缩路径，目录排在文件之前，文件名中段截断并保留扩展名。筛选匹配完整路径；窄目录中的增删数通过完整提示保留。顶部路径栏展示当前位置，提供差异、源码与 Markdown 预览；不提供未实现的编辑操作。内容始终来自已确认的历史工具结果，目录树不冒充完整工作区目录。

检查栏默认 400px，实际并排宽度不超过会话区域的 40%，在有效范围内保留已保存偏好。文件树固定在左、阅读区在右，并排与最大化沿用同一结构；工具栏文件夹按钮可收起文件树，让正文独占整栏。差异渲染由 `@archer/ui` 的 `HistoricalDiff` 提供，宿主只传两侧原文，组件不读取文件。Diff 行号固定占列且禁止换行，代码保留空白并横向滚动，不把多位行号拆成多行。

### 检查器最大化与专注阅读

最大化时文件检查器覆盖整个工作区，窗口操作固定靠右，条目导航保持固定上限。最大化阅读面必须是不透明整窗层：macOS 外壳为透出系统毛玻璃使用透明背景，工作台面板不能复用外壳的 `workbench` 类，否则最大化固定层会继承透明背景，把侧栏、会话与输入区透到阅读内容下方。中间阅读内容限制在 960px 内，工具参数的长命令使用横向滚动，不把文字拉满整个窗口。空正文不渲染输出框；同时没有工具调用时显示明确空态。工具调用按名称、参数、原始 JSON 分层，原始身份与载荷完整保留，JSON 默认折叠。

最大化工具栏提供专注模式，临时隐藏会话侧栏；再次点击恢复，退出最大化或按 Esc 后也恢复。此状态不写入本机侧栏偏好；macOS 专注模式给原生窗口按钮保留空间。右侧条目的字号、行高与选中质感不因最大化改变。验证包括桌面构建、Lint、检查工作区导航及结构化调用展示测试，不执行浏览器测试。

### 主题与明暗

中性石墨灰白是 Graphite 界面主题的表现，也是默认组合的背景与文字层。外观模式、界面主题与强调色独立管理：四套界面主题（Graphite、Midnight、Slate、Warm）决定中性层，四套预设加自定义强调色决定交互强调，跟随系统只决定最终明暗。主题、字号与结构密度相互独立；更换界面主题不改变强调色、布局、品牌 Logo、事实与授权语义，更换强调色也不改变中性背景。完整机制见 desktop-ui-spec.md 的主题边界与 desktop-theme-system.md。

## 整体基线与信息组织

[四态母版](../design/desktop-baseline.html)将界面固定在 320px 项目导航、弹性任务区与 400px 普通检查器。上下文页不外接右侧检查器：页面内以 Resizable 分栏，默认左 66% / 右 34%，右栏固定承载请求概览、已选上下文与整理事实，选择条目只替换「已选上下文」内容；最大化用于长代码或日志。文件检查器不显示标签栏，最大化与还原入口固定靠右。

答复后的结果摘要统一呈现真实结束状态、历史变更与需关注入口。耗时、调用次数、模型与累计用量放在默认关闭的运行详情，不挤占主要阅读层。历史恢复异常移到侧栏底部的图标数量入口。上下文按消息角色、工具声明与参考整理分组，并提供类别筛选、搜索、字符条带跳转与近期 Token 趋势；原始运行事件按任务身份折叠并支持需关注筛选。分组不修改原文、编号、顺序或原始 JSON，不依据工具成功推断整轮完成。

普通设置的控件列为 196px，分组间距 16px；分段控件仅收紧内部水平留白，不修改共享字号、图标或选中态。事件检查采用任务、实际交互与原始事件三层结构，范围与筛选放在固定的视图工具栏，一级视图由中间会话工作区统一管理。

设置的能力来源使用 [Provider 浏览规范](../decisions/provider-browsing.md)：入口两列小卡片，窄时单列；点击后在当前正文中进入能力列表及契约详情。该结构与旧检查器的来源分组不是同一使用目的，不把全局来源当成请求快照。


### 来源与能力的双列浏览

设置中的一级 Provider 和二级能力（含技能与搜索结果）统一使用双列横向小卡片，内容区域不超过 720px 时收为单列。Provider 高度 88px，能力卡片高度 112px；名称单行截断，用途最多两行，来源与执行声明独立呈现。截断只影响列表，详情保留完整声明。

彩色资源图标使用用户提供的 `现代应用图标网格界面.png`，原图保存于 `apps/desktop/renderer/src/assets/capability-icons.png`，由 CSS 图集窗口显示无文字的图标区域。图标尺寸和图集刻度集中在 design-tokens.css。Provider 与已知技能通过有限的本地展示映射选择图标，未知技能使用书本，未知来源使用系统图标；不再按身份随机分配颜色或徽记。图标映射不参与 Camp 解析、能力分类、授权或执行，不添加图中尚未接入的入口。

三级详情继续采用单一阅读区，不双列展示技术正文。按钮、导航和活动图标继续使用 Phosphor regular。图集保留原图的浅色底座，深色外观中也不对图标反色；暗色专用画稿尚未提供。

### 目录行操作菜单

项目目录保持本机记录顺序，点击选择不自动置顶，新打开的目录追加到末尾。顺序由本机导航偏好保存，不影响服务端会话事实。验证覆盖重复选择与重新打开后的顺序保持。

侧栏真实工作区的目录行只在行尾保留一个浮层菜单按钮，悬停或键盘进入时显示，无悬停设备常显。菜单集中提供“新建对话”和“从侧栏隐藏”，两项统一使用 `@archer/ui` 的 `DropdownMenuItem`，共享字号、行高、间距与悬停样式；隐藏仅移除导航入口，不再并排两个图标，也不为按钮预留常驻文字列；目录名提前截断，长文本不因按钮出现而移动。“其他会话”不是工作区，不提供目录级操作。空目录没有子行时仍可通过该菜单新建对话。

新建对话选择该目录并进入新对话输入页，复用既有工作区选择流程，不立即创建 Agent，也不影响当前运行任务。隐藏只改变本机导航，保留目录与会话。该行为只涉及桌面导航，不修改 Runtime、权限或事实。验证使用桌面构建、类型检查、Lint 和桌面 renderer 测试；实际悬停、键盘及视觉质感需要 Electron 窗口验收。

### 检查器的打开与收起入口

检查器关闭时，对话顶栏显示“打开检查器”；展开后隐藏该入口，由文件检查器右上角统一提供“最大化 / 还原”和“收起检查器”。最大化不改变这些操作的位置。文件检查器没有页签与关闭页签操作，收起整个检查器后键盘焦点返回重新出现的打开入口。

该规则只调整入口显示与焦点交接，沿用现有文件对象、本机布局与最大化状态管理，不影响任务或执行事实。验证使用检查工作区行为测试、桌面类型检查和 Lint；实际布局仍需 Electron 验收。

### Dock 品牌标志的视觉重量

应用图标保持 1024px 画布、824px 白色底座与四周 100px 透明边距。底座内的 A 与箭头围绕中心放大 6%，以原渐变增加 4 单位圆角描边，改善小尺寸识别；favicon 使用相同标志。侧栏品牌图形保持原比例。PNG、ICO、ICNS 从同一 SVG 造型生成，验证尺寸、透明边距与多尺寸预览。Dock 实际显示需重启应用加载新资源。

### 侧栏导航节奏

侧栏以品牌行、轻量新对话、与行同底色的搜索、项目目录与底部工具行组织。品牌和新对话之间不累加大段外边距，目录组之间不另留间距，目录行保持 32px 标准高度。默认只展开当前项目。新对话使用普通文字色，强调色留给焦点与当前项目的文件夹图标；设置快捷键使用无边框辅助文字。

工作区从目录行浮层菜单的新建对话进入，添加工作区统一使用项目标题右侧的文件夹入口；底部只保留设置、恢复异常和服务状态，不重复显示工作区选择器。顶端新对话仍沿用当前工作区。调整仅影响桌面导航呈现，不改变会话与执行机制。验证使用桌面构建、类型检查、Lint 与导航相关测试，视觉效果需 Electron 实机验收。

### 完全访问确认窗口

完全访问确认使用 small 窗口和共享标题、按钮、操作栏。窗口只保留一层 16px 内边距，标题使用普通文字色；正文先说明任务范围，再说明当前待授权命令，宿主权限、文件访问边界和执行结果说明使用辅助层级，完整保留语义。取消默认聚焦、Esc 关闭和确认提交逻辑沿用原行为。验证采用桌面构建、授权测试与 Lint；实机视觉另行验收。


## 样式模块与维护边界

index.css 只声明依赖顺序，不承载页面规则。design-tokens.css 管理刻度与颜色，surfaces.css 管理公共按钮、表单、菜单、Dialog 和浮层；settings.css 与 inspector.css 管理专用工作区。其余规则按原始级联顺序分为 foundation、navigation、workspace-layout、composer、conversation、activity、workspace-details、workspace-content、capabilities、workspace-interactions。

区域模块保持连续加载顺序，跨区域联动与最终工作区状态集中在 workspace-interactions，不通过业务主题选择器覆盖布局。新增公共控件进入 Surface 与 surfaces，不复制到区域模块。禁止在 index.css 末尾追加补丁；涉及旧规则时修改所属模块，删除已失效声明。当前命名用于样式职责，不要求移动 React 组件或改变公共 API。

窗口背景使用 surface-frame，阅读层使用 canvas，设置内容使用同一阅读层，控件用 panel，菜单与 Dialog 使用 surface-floating；工作区页签与活动筛选使用统一的强调色层级，导航会话选中使用中性浅表面。按钮按下使用 state-pressed，交互过渡读取 motion-feedback；减少动态效果的系统偏好关闭装饰性过渡。


## UI 源码模块边界

实际源码根目录为 apps/desktop/renderer/src/ui。

| 模块 | 职责 |
| --- | --- |
| theme | 主题解析、主题标识和 Design Tokens |
| layout | 应用入口、窗口框架与基础布局 |
| primitives | 图标、按钮、浮层、分段选择及 Markdown 阅读组件 |
| navigation | 侧栏、工作区与会话管理入口 |
| workspace | 对话、输入、执行时间线、Plan 和人工交互 |
| panels | 变更、活动、上下文及检查器容器 |
| settings | 设置工作区、模型、上下文策略和能力浏览 |

应用启动由 main.tsx 装配 layout/App；index.css 按显式顺序导入模块样式，不提供旧路径别名或转发导出。模块内部相对引用，跨模块明确引用目标文件。theme 不依赖业务组件；primitives 不接管任务状态；layout 装配业务模块。共享 Client、纯数据投影和本机状态继续留在 lib / store，不为目录整齐复制状态或 I/O。

panels 是执行事实检查器，不能承担 Provider 全局配置。settings 是应用内完整工作区，不创建新窗口或强制系统全屏。组件迁移不改变 Runtime、Contract、事实或权限语义。


### 紧凑控件焦点

公共按钮、关闭入口、选择器、开关、页签与对话折叠入口的键盘焦点使用 1px 语义焦点色细线，向内偏移 1px，不在控件外形成悬空框。计划等记录标题沿用记录表面的圆角，展开后底边保持平直。焦点提示使用 `:focus-visible`，普通鼠标点击不额外绘制焦点框；保留浏览器对键盘焦点的判定，不通过移除焦点或拦截按键隐藏提示。输入组继续沿用自身的单一焦点边界。

验证时分别检查鼠标展开与 Tab / Shift+Tab 聚焦计划、记录、按钮和选择器，确认键盘焦点可见、边界不越出紧凑行；同时检查明暗主题。桌面构建与现有阅读布局测试验证样式集成，不能替代窗口中的视觉验收。
