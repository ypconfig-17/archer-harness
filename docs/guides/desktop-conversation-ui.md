# 主对话组件映射

本规范定义 Archer Desktop 主对话中“内容类型 → UI 组件 → 默认形态 → 点击去处”的唯一映射。视觉刻度与整体结构见 [desktop-ui-spec.md](desktop-ui-spec.md)，计划身份与提交边界见 [计划声明与连续执行流](../decisions/task-plan-declarations.md)，投影取舍见 [对话优先的首条消息呈现](../decisions/conversation-first-message-presentation.md)。

规范只约束 Renderer 展示投影。事实、Turn、Effect、授权与恢复语义不因组件映射改变。

## 六种核心 UI 与两个辅助 UI

| 内容类型 | 组件 | 默认形态 | 出现位置 |
| --- | --- | --- | --- |
| Agent 公开反馈 | `ProgressParagraph` | 开放式 Markdown 正文，原文有标题才显示标题 | 主对话，按事实顺序 |
| 工具执行活动 | `ActivityGroup` | 紧凑活动组；连续已结束调用折叠为一行 | 所属公开反馈之后；没有反馈时直接按真实顺序 |
| Plan 创建/修订 | `PlanEventRow` | 一行轻量事件 | 计划确实创建或结构修订的历史位置 |
| 用户询问/授权 | `HumanInteractionCard` | 独立交互卡片；回答后收成一行 | 阻塞操作原位置 |
| 最终回答 | `AssistantAnswer` | 标准 Markdown 正文 | Turn 结束处 |
| 当轮执行汇总 | `TurnSummary` | 一条状态摘要，默认收起 | 该 Turn 首个普通活动片段 |

辅助 UI：

| 组件 | 职责 | 出现位置 |
| --- | --- | --- |
| `ActivePlanBar` | 当前有效计划的入口：「当前计划」标签、标题、完成数、「模型声明」，展开显示全部步骤 | 输入区上方 |
| `EventPanel` | 已提交事件的筛选、列表与单条记录详情 | 中间「活动」页 |

实现名称：`ConversationActivity` 生成 `ProgressParagraph` 段落，`ActivityGroup` 与 `PlanEventRow` 是对话组件，`HumanRecord` 承担已回答/已授权形态，待处理表单由 `pendingInteraction` 在原位置渲染，`AssistantAnswer` 由 Turn 终态事实渲染，`ExecutionSummary` 是 `TurnSummary`，`CurrentPlan` 是 `ActivePlanBar`，中间「活动」页承载 `EventPanel`。

## 分段组成

“段落”不是新增领域实体，也不为每段新建卡片。一个阅读段落由 `ProgressParagraph` 与其后连续的 `ActivityGroup` 共同组成：

1. 模型明确输出的公开文本开启一个段落；正文内已有的标题照常渲染，Renderer 不提炼、不改写标题。
2. 其后的连续普通调用按原事件顺序缩进归入该段落。
3. 下一条公开文本、用户补充输入、人工交互、计划事件或 Turn 结束形成边界。
4. 没有公开文本时不创建段落，只显示中性工具组，不写“正在分析”“正在修复”等推断标题。
5. 原始推理（reasoning）不进入主对话，不作为段落起点、预览或标题。

## 组件规则

### ProgressParagraph

- 读取：非最终答复的 INFER 公开文本。
- 视觉：常规正文 14px；原文有标题才显示标题；段落间距 24px；不套卡片、不加状态边框；组头时间只取已加载 Turn 开始事实。
- 缺数据：没有公开文本不创建段落；流式临时正文标明未提交，提交后由同一 INFER 结果原位替换。

### ActivityGroup

- 读取：段落内连续普通 CALL 与已提交的 `durationMs`。
- 默认：已结束的成功调用按原序折叠为一行「工具活动 · N 次调用」，右侧按已提交调用显示读取 / 修改 / 执行 / 其他分类计数；运行中、失败、未知与取消调用保持可见并显示真实状态。
- 单行：动作、目标、状态与耗时；Shell 只显示单行命令预览，长路径省略但保留完整提示。
- 展开：在原位列出同序短行，不切换标签。
- 短行：只做定位与扫读；完整参数、命令、cwd、输出与退出信息统一在「活动」页选择对应记录阅读，不在对话内再开第二层详情。
- 禁止：跨过用户询问、公开反馈或人工交互聚合调用；用工具名、命令或计划步骤生成阶段名；把折叠行当作整轮完成证明。

### PlanEventRow

- 读取：已提交计划声明的 `created` / `revised` / `snapshot` 记录。
- 默认：一行事件，显示「已创建计划 / 已调整计划 / 已加载计划声明」、标题、步骤数与「模型声明」。
- 展开：当次声明、版本、步骤与调整前的阶段，展开区限高滚动；未加载更早版本时说明范围。
- 禁止：把完整步骤列表直接铺进执行正文；把纯进度更新渲染成新节点；把阶段标题当作执行段落标题；把计划状态换算成工具结果或完成率。

### HumanInteractionCard

- 读取：`ASK_HUMAN` 与人工 CALL 的暂停、恢复与结束事实。
- 等待：显示实际问题、选项或输入字段、提交动作与授权范围；有选项时标题为「需要你的确认」，使用单选项语义并提供「确认并继续」，命令授权与普通回答使用不同文案与图标，不混用。
- 回答后：原位收成一行「已回答：…」或「已授权本次命令」；点击仍可查看原问题与答案。
- 禁止：把拒绝、取消、失败或未记录回答显示成有效答案；把 `approved` 当作命令执行成功；成功响应前伪造已回答状态。

### AssistantAnswer

- 读取：Turn 终态事实中的正式答复。
- 形态：标准 Markdown 正文，可有标题、列表、表格与代码块；只显示一次。
- 禁止：并入工具失败、原始 JSON、计划进度或重复的 Agent 头部。

### TurnSummary

- 读取：该 Turn 已加载的普通调用、工具确认的文件修改、已知耗时与片段状态。
- 形态：每 Turn 一条状态摘要，默认收起；显示已加载工具调用数、文件变更构成（修改 / 新增 / 未知）、耗时与运行/结束状态，右侧固定「查看全部活动」。
- 展开：累计调用列表，按原序；调用明细仍需逐项展开。
- 缺数据：零工具调用不生成摘要；历史不完整时标为「仅已加载记录」，不声称完整数量；计划步骤不进入摘要。

## 页面映射

| 页面位置 | 展示内容 |
| --- | --- |
| 会话标签 | `ProgressParagraph`、`ActivityGroup`、`PlanEventRow`、`HumanInteractionCard`、`AssistantAnswer`、`TurnSummary` |
| 活动标签 | 已提交事件时间线、筛选、单条记录参数与原始 JSON |
| 上下文标签 | 已提交 INFER 请求快照：请求指标、可折叠字符占比条带、近期 Token 趋势、默认收起的分组条目、请求概览、已选上下文、整理事实与原始 JSON |
| 输入区 `ActivePlanBar` | 当前有效计划的全部步骤与进度声明 |

主对话不承载全部原始事件，也不退化为只有调用计数的统计行。调用详情、会话概览与请求级能力来源不作为活动页的二级视图；请求快照在独立的上下文页阅读，能力来源在设置中阅读。

## 事实边界

以下限制来自已提交事实，不由 Renderer 补齐：

- 没有“段落实体”，也没有把某个 CALL 归属于某条公开反馈的字段；分段只表达时间相邻，不声称语义归属。
- 只有 INFER 公开文本可作为段落起点；reasoning 不保证可公开，不能改写为进度。
- 计划步骤是模型声明，不是执行事实；工具成功或 Turn 完成不能替代计划更新。
- Shell 命令文本只表达执行意图，不据此推断阶段、安全性或文件影响。
- 调用耗时只取 `effect.completed` 的 `durationMs`；文件修改只统计工具确认的 `fileChange`。
- 历史窗口不完整时，调用数、文件数与时间范围都只描述已加载记录。

若模型没有公开反馈或稳定分组数据，界面只渲染中性工具组，并明确这是数据契约限制。要让主对话出现更多自然段落，需要在 Agent/提示词层让模型输出可公开的进度文本；该能力尚未实现，本规范不通过 Renderer 伪造。

## 实现与验证

- `ConversationActivity`、`ActivityGroup`、`PlanEventRow`、`HumanRecord`、`ExecutionSummary` 位于 `apps/desktop/renderer/src/ui/workspace/EventTimeline.tsx`；`CurrentPlan` 位于同目录的 `CurrentPlan.tsx`；活动页由 `apps/desktop/renderer/src/ui/panels/EventPanel.tsx` 承担。
- `tests/desktop/renderer/execution-timeline.test.ts` 覆盖段落切分、折叠顺序、失败可见、计划事件行、摘要、人工交互与原始推理隐藏；`reading-layout.test.ts` 覆盖零调用摘要、默认收起与活动入口；`accent-usage.test.ts` 覆盖当前步骤的浅强调。
- 静态渲染测试证明投影与结构，不代替 Electron 对字号、密度、键盘、滚动与窄窗口的视觉验收。

### 输入附件

新建任务与会话续聊均支持图片和 UTF-8 文本文件，每条消息最多 4 个附件；图片上限 5 MiB，文本上限 256 KiB。粘贴达到 4,000 字符或 80 行的文本会自动成为 `pasted-text.txt` 附件，短文本直接进入编辑框。文本内容随输入事实保存，恢复无需读取本地文件；不支持的二进制文件明确拒绝。可运行 `pnpm test tests/desktop/renderer/composer-attachments.test.ts` 验证内容转换与粘贴阈值。

## 输入区发送与停止

输入框右下角空闲时显示发送箭头，有活跃 Turn 时在同一位置显示停止方块，使用普通按钮提交当前 Turn 的取消请求，不触发表单发送。停止不受草稿是否为空影响；请求期间及事实处于 cancelling 时禁用按钮，名称与提示为「正在停止…」，直到 Turn 结束才恢复发送。取消请求不代表外部执行已经停止，不改变 Runtime 的提交与确认边界。

运行中仍可通过输入框的 Enter 提交排队或补充输入，发送方式由现有选择器决定。等待用户交互且输入框收起时，保留交互区的停止文字入口；展开输入框后只使用右下角停止键。验证覆盖空草稿停止、取消确认期间禁用、结束后恢复发送及排队输入。

## 工具调用行

会话中的工具活动与活动页调用表共用 `apps/desktop/renderer/src/ui/workspace/InvocationRow.tsx`，统一名称、图标、目标摘要、状态和耗时的事实投影。会话使用紧凑模式，活动页增加时间、类型和 Token 指标并支持选择详情；会话行点击以 `turnId/effectId` 定位活动页的同一调用详情；宿主统一维护选中身份，中间活动页与右栏活动入口共用选择。无详情入口的独立预览仍显示普通文本。工具分组仍按原事实顺序折叠，运行、失败和未知调用保持可见。

紧凑行使用可收缩摘要列与不换行的状态、耗时列。长命令和文件路径单行省略，完整摘要通过悬停可读；状态与耗时不逐字换行，不因参数长度撑高列表。字体取统一 Token，不改执行事实、工具分组或事件恢复规则。

验证运行桌面类型检查，以及 `tests/desktop/renderer/event-panel.test.ts`、`tests/desktop/renderer/execution-timeline.test.ts`。视觉验收展开包含长 Shell 命令的工具组，检查桌面和窄会话列下的摘要省略、状态完整性、活动页选择和键盘上下导航。

工具组展开内容使用 `@archer/ui` 的 `ScrollArea`，最大高度统一取 `--brief-activity-max-height`（280px），超过后仅调用列表内部滚动。折叠入口不随内部列表滚动，滚动到边界不继续带动外层会话；短列表按内容自然占高。运行及异常调用仍独立保留。全局非键盘焦点移除浏览器默认 outline，键盘 `:focus-visible` 保留边界内提示，输入与选中、错误状态不被清除。

验收补充：鼠标点击工具组、计划与菜单入口不出现原生外框；Tab 导航保持可见焦点。展开长工具组检查 280px 高度上限、短组自然高度、内部滚动与折叠后状态。

调用状态通过语义色区分：已完成使用 success、进行中使用 accent、失败与需关注保留 error / warning，中文标签始终保留。任务进入任意终态后，未完成计划显示「计划未完成 · 执行已结束」，当前步骤停止动画并使用弱化颜色；模型声明的完成数不变，不伪造步骤完成事实。`Plan.executionStopped` 仅控制展示，不改变计划日志。验收覆盖余额不足失败、取消和正常结束但计划未更新的情形。

对话工具活动与活动页不各自保存一份工具结果。`InvocationRow` 共用 `operationDisplay / operationState` 投影，详情统一由 `EventPanel` 根据选中身份解析当前已加载事实，显示同一输入、输出和指标。跨入口定位清除搜索并切回调用视图、解除类型筛选；关闭详情清除宿主选择，切换 Agent 也清除选择。详情读取范围仍受已加载事件窗口限制，不补造缺失记录，不触发工具重执行。

## 公开反馈与空正文

过程正文只展示模型实际返回的公开 content；reasoning、工具调用与计划声明均不等于公开反馈，不能由 Renderer 将它们转换成模型答复。复杂任务的系统提示要求在实质调查前给出初始说明，并在重要发现、阶段结果、阻塞或方向变化时继续输出简短正文；即使同次调用请求工具，公开反馈也必须写在正文中。普通调用不逐条播报。

这是模型输出约束，不提供强制频率保证，不改 Effect、日志或恢复语义。修改提示只影响后续推理，不会为历史空正文补造内容；最终答复仍在已提交 Turn 结束事实的位置展示。验证运行 Agent 提示词测试；实际模型验收检查长工具序列间是否有公开反馈，不能以提示词测试通过替代模型行为验收。

侧栏子会话入口统一左对齐。共享 Sidebar 子导航显式声明 `text-align: left` 与起始端排列，使用按钮或链接渲染时保持相同文字起点，短标题不居中；菜单与状态点仍固定在行尾预留区，悬停与选中不改变缩进。

## 自动历史与会话定位

会话不提供手动「加载更早记录」入口。打开后先显示最近事实，随后按页自动补齐历史与任务索引，避免单次无界请求阻塞首屏。旧记录插入时保留用户阅读锚点；处于跟随最新模式时不因补历史切换到手动阅读。同一历史游标失败不自动无限重试，错误明确显示。

会话右侧提供轻量横线定位条，每个入口对应真实 Turn，点击复用任务导航的事实加载与定位逻辑，不重新执行任务。定位条独立于正文滚动，条目过多时内部滚动；按钮提供任务时间与状态提示、可访问名称。验收覆盖超过一页历史、边补齐边接收新事件、手动阅读锚点以及跨历史任务跳转；本地运行不代表 DOM 渲染或 Markdown 解析开销无限，分页属于后台读取方式，不是用户操作步骤。

定位条在会话阅读区右侧垂直居中；使用共享 Button、Tooltip 与 ScrollArea 组合，不新增专用控件。少量条目自然占高，长列表限制在视口高度的 60% 内并内部滚动。

### 输入草稿的渲染边界

会话草稿仍由进程内草稿存储保存，切换会话保留，发送确认后清空，不进入事件日志。草稿订阅仅放在输入控件与发送按钮中；会话页面不订阅逐字更新，避免输入时重新计算历史答复、Markdown 排版和检查器。发送按钮独立读取同一草稿，空文本与附件判断保持即时更新，不对输入做延迟处理。

验证时在包含长答复和代码块的会话中连续输入及使用中文输入法，使用 React Profiler 确认逐字更新不提交整个 AgentDetail 子树；同时检查空文本禁用、附件发送、发送后清空与切换会话保留草稿。

### 阶段回复正文排版

Agent 阶段回复（如“明白，我来……”）与最终回复共用 `@archer/ui` 的正文排版基线：字体、字号、常规字重、行高与正文颜色均取相同语义 Token，再由同一 Markdown 入口排版。阶段回复组件显式设置基线，不继承活动区域的小字号；桌面业务样式不重复覆盖字体。执行状态和调用统计继续使用各自的辅助文字刻度。

验收时对比同一段文字的阶段回复与最终回复，检查默认及调整字号后的字体、字号、字重和行高一致，并在窄窗口下复核 Markdown 排版。

### 实时更新的性能边界

Markdown 正文按文字和流式状态进行 React memo 比较，任务计时及其他推理的增量不重新渲染未变化的历史正文；主题变化由 Markdown 自身订阅，仍会更新图表。当前流式正文继续立即更新，不增加人为吐字延迟。

Agent 事件缓存对按序增量直接追加，仅对传入批次排序去重；历史补齐及重连重叠使用完整合并，相同序号以后收到的事件为准。空批次和相同事件引用的重复补齐不发布状态变化。事实内容、游标及恢复语义保持不变。行为验证运行 `tests/desktop/renderer/agent-stream.test.ts`；界面验收在长会话运行任务时输入、滚动并切换主题，用 React Profiler 检查历史 Markdown 不随计时或其他正文增量重新渲染。以上优化不代表已有整机性能测量结论。

面板可见性准入、原始 JSON 按需生成、独立耗时文字、自动行为验证及 Renderer / Backend 可执行采样方法见 [桌面性能边界与采样](desktop-performance.md)。
