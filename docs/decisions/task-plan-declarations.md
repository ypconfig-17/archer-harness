# 计划声明与连续执行流

## 保护的性质

主对话以真实执行活动为主线。计划提供方向和阶段进度，不作为执行容器，也不证明工具结果或任务目标正确。人工询问、命令授权和结果未知各自保持明确语义，界面刷新后从已提交事实恢复。

原有完整阶段列表无法区分新计划与修订，也不能拒绝过期更新。计划身份与连续版本用于保护这一边界；现有 CALL 和结果元数据已经可以记录声明，因此不新增 Effect、计划注册中心、Task / Run 宿主或会话状态字段。

## 声明协议

内置 `files.plan` 使用 `action`、`planId`、`title`、`expectedRevision`、`steps` 和可选 `explanation`。标题、阶段与说明使用用户语言。

- `create` 要求 `expectedRevision: null`，成功结果从 `revision: 1` 开始。`planId` 是本 Turn 内由模型明确给出的稳定身份，不能复用已创建身份。
- `update` 要求当前计划身份和最新已提交的 `expectedRevision`，成功后连续加一。每次提交完整标题与阶段列表，新增阶段或改变路线仍更新原计划。
- 一份计划最多有一个 `in_progress` 阶段。当前计划所有阶段明确声明为 `completed` 后，才能创建下一份独立计划。创建后不能更新更早计划。
- 计划身份仅在本 Turn、固定 CapabilityRef 内有效，不自动跨 Turn 延续，不支持并行计划或父子计划。后续 Turn 可以使用相同局部身份。
- 标题最多 120 字符，身份为 1–80 个 ASCII 字母、数字、下划线或连字符，阶段为 1–30 项，每项最多 500 字符，说明最多 2000 字符。状态仅接受 `pending`、`in_progress`、`completed`。

创建、更新及冲突均走普通 CALL。冲突明确拒绝，不推进版本，也不把拒绝解释为计划成功。所有阶段状态均是模型声明；Turn 完成、命令成功或文件回执不能替模型补全阶段。

## 提交与恢复

Provider 不保存计划进度。每次调用从现有只读 `HistoryReader` 分页列举本 Turn、精确 CapabilityRef 的已提交成功调用，再读取完整结果并重建声明序列。Handler 注入当前调用的 Turn 与能力引用，不让模型提供或伪造此上下文。

`HistoryReader.list` 每页最多 128 项，返回调用身份与业务错误标记；`read` 保持每页最多 8192 字符。计划重读的单份结果最多 128 Ki 字符。历史歧义、非法格式或超限明确拒绝本次调用，不猜测版本。失败、未提交、结果未知及其他 Turn 或来源版本的结果不推进计划状态。

当前每 Turn 至多一个在途 Effect，Runtime 串行提交并在调用前固定历史快照，因此校验与下一份计划声明之间没有本 Turn 的并行更新。提交失败或确认未知仍由 Runtime 隔离，成功计划不能靠 Provider 内存提前生效。恢复只重建声明；已提交成功的 CALL 不重新执行。

内置工作区工具 identity 的实现 revision 为 2，明确表达计划输入协议变化。来源不匹配仍按固定引用阻止继续执行，不提供旧声明的兼容适配或数据迁移，不删除旧日志。

## 主对话投影

模型公开过程正文直接沿时间线展示，原始思考单独折叠。相邻普通工具调用合并为一条可展开记录；模型反馈、用户输入、计划记录和人工交互都会断开工具组。后续活动不能因为归属同一 Turn 就移动到先前输入前面。

创建计划与修改标题、阶段结构在主对话和完整活动视图中共用一行轻量记录，分别显示「已创建计划」「已调整计划」。纯阶段状态更新不新增可见节点；声明历史仍保留，可从计划记录查看各版本。创建记录的展开区域提供该计划在已加载范围内的最新声明与版本列表，调整记录保留当次声明及已加载的前一版阶段。加载窗口从后续版本开始时使用「已加载计划声明」，明确创建及更早声明尚未加载，不将进度更新猜成创建或结构修订。

主对话简版不为计划生成段落、卡片或摘要区块：计划阶段不是执行事实，不能用阶段标题充当工作段落标题。创建与结构修订只在历史位置保留一行计划事件，显示标题、步骤数与「模型声明」，点击查看版本与步骤变化；纯进度更新不新增可见节点。当前 Turn 存在声明时，另在输入区上方保留一行计划入口，显示标题、完成数与来源，展开后列出全部阶段并用轻选中表面标出当前阶段；完整修订历史通过活动视图阅读。执行摘要只汇总真实工具调用数、文件修改数与需关注项，不承载计划进度。新 Turn 没有声明时不沿用旧计划；已知声明未加载时明确说明范围。

待处理询问、命令授权或未知结果对账在对应操作位置展开。回答后原位折叠为已回答记录，授权后保留单次授权记录，工具执行结果仍独立显示。拒绝、取消、失败和未记录回答不冒充有效答案。提交中禁用重复动作，提交失败保留表单和错误，成功响应后等待事实同步，不提前伪造已回答状态。

已知等待项的创建事实尚未加载时，在当前时间线末端提供入口并说明记录范围，不能静默隐藏操作，也不伪装成历史位置。等待卡片已表达需要介入时，不再重复显示等待阶段提示。

## 验证

`tests/archer/task-plans.test.ts` 验证重复身份、过期修订、并行创建与旧计划更新被拒绝，完成后新建计划、历史精确来源分页，以及重启后回答原询问继续原计划；后续 Turn 不继承计划版本。

`tests/desktop/renderer/execution-timeline.test.ts`、`process-presentation.test.ts`、`reading-layout.test.ts`、`task-insights.test.ts` 验证活动顺序、内联询问与授权、未知结果入口、历史加载边界，以及简版计划事件只有一行、步骤仅在展开区、纯进度更新不新增节点、输入区入口展示标题、完成数与阶段。人工凭证、拒绝和未知结果恢复仍由既有 `tests/archer/human-interaction.test.ts` 覆盖。

界面测试验证投影和结构，不代替 Electron 对字号、密度、滚动及窄窗口的视觉验收。
