# 面向任务连续性的 Archer 上下文设计提案

## 设计性质与目标

本文讨论任务连续性的设计依据；结构化交接、事实参考和只读历史接口的当前边界见 [摘要与证据决策](context-evidence-boundary.md)，模型任务质量评测仍未完成。现有运行行为以 [Handler 实现说明](../architecture/handlers.md) 和代码为准。

目标是在明确的窗口与成本约束下，保留继续正确执行任务所需的状态。原始事实无损、上下文可有损、关键证据可取回；压缩率不是首要目标。所有质量收益均需 Archer 自身实验验证。

设计保留 Camp、Contract、Effect 和 Kernel 的现有职责；不引入新宿主、注册器、目录寻址、并行 Effect 或日志 checkpoint。

## 论文依据与适用范围

| 原始资料 | 可采纳的证据 | 不能直接推出的结论 |
| --- | --- | --- |
| [Lost in the Middle，TACL 2024](https://aclanthology.org/2024.tacl-1.9.pdf) | 在其问答与键值检索实验中，信息位置影响模型使用长上下文的表现 | 不能证明所有当前模型、代码任务或压缩策略具有相同位置偏差 |
| [LongLLMLingua，ACL 2024](https://aclanthology.org/2024.acl-long.91.pdf) | 问题相关的信息选择和重排在部分任务中兼顾压缩与准确率 | 文档问答结果不能外推成代码执行收益；不应任意重排原生工具消息 |
| [MemGPT，公开预印本](https://arxiv.org/html/2310.08560v2) | 工作上下文与可检索外部记录分离是一种有效系统设计 | 不意味着 Archer 需要照搬它的调度器、共享记忆数据库或控制流 |
| [SWE-Pruner，2026 公开预印本](https://arxiv.org/html/2601.16746v1) | 当前信息需求引导的行级选择区别于按年龄或字符截断；其方法含训练过的选择模型 | 不能将任意关键词筛选或头尾截断宣称为论文算法的复现 |
| [AutoCompact，2026 公开预印本](https://arxiv.org/html/2610.02163v1) | 压缩时机、工作状态与压缩后的行动需要联合考虑；方法包含监督与强化学习 | 给未训练模型增加 compact 提示词，不能视为具备相同能力或收益 |
| [Compact-Bench，2026 公开预印本](https://arxiv.org/html/2610.31710v1) | 相同仓库状态下的成对续跑能检测任务损害；保留标识符不保证保留有效行动进展 | 其特定样本和细节指标不能当作 Archer 的准确率或总信息损失比例 |
| [CompactionBench / APEC，微软公开预印本](https://www.microsoft.com/en-us/research/wp-content/uploads/2026/10/CompactionBench_preprint.pdf) | 重复压缩的前台等待、缓存损失与任务质量需要一起衡量；分段稳定前缀值得研究 | 生产轨迹规模不等于效果实验的独立任务数，最高成本收益不是普遍保证 |

Compact-Bench 与 CompactionBench 是不同研究。后者的主要效果评估使用八个版本演进任务，生产分析则覆盖更大规模会话。其生产阈值存在明显差异、中位约 66%，APEC 还会提前准备摘要：这些证据不支持“所有系统都应尽可能晚地压缩”。Archer 的保守默认是待验证的基线，而非论文证明的最优策略。

## 上下文的内容与权威

模型请求由现有消息协议表达，下表只定义保留语义，不新增消息角色或持久化会话容器。

| 内容 | 来源 | 保留和权威规则 |
| --- | --- | --- |
| 系统规则、工具声明和明确项目准备安排 | Archer 与固定能力声明 | 稳定前缀，不因摘要增加权限；准备内容依然是非可信参考 |
| 用户原文 | 已应用的输入和引导事实 | 保留原文及顺序；不将工具数据或模型摘要提升为用户指令 |
| 执行状态参考 | 已提交 CALL 结果、未知状态与明确变更回执 | 确定性投影，不经 LLM 改写；只陈述记录能够证明的事实 |
| 工作交接摘要 | 已确认的摘要推理响应 | 保存假设、排除原因、决策依据、阻塞与下一步；始终是模型生成参考 |
| 近期完整交互与主动取回的证据 | 原始消息、已提交工具模型正文 | 按 token 体积和调用配对保留；被压缩的历史仍可有界读取 |

用户原文仍是用户层级信息，不能覆盖系统规则。队列中未应用的输入、未消费的引导、原生 user 角色承载的系统观察，不能仅凭角色被当作已生效用户要求。

默认不自动从用户原文提取一套“可信硬约束库”。模型提取可能出错；需要精简用户原文时应另行设计显式用户确认事实，不能靠模型自评提升权威。本提案接受用户原文持续增长最终导致超窗的限制。

### 执行状态与交接摘要分开

执行状态参考从事实机械生成，例如：

- 工具调用已经完成、失败、取消，还是副作用未知。
- 文件变更回执确认了哪些路径与内容 revision。
- 某次测试进程的退出码及输出来源。
- 某次未知操作已被人工放弃追踪；放弃不等于外部操作失败。

`completed` 仅表示能力执行收束；命令返回非零退出码或显式 isError，不能写成任务验证成功。Shell 命令包含文件路径也不能证明修改已发生；没有回执的操作不猜测文件变更。

事实投影仅作为参考数据，不提升成 system 指令。作用域为当前 Turn 和未收束事项，再补充明确需要的历史回执；不能把所有历史操作清单永远钉住。若必要事实本身过大，明确报告预算不足。

交接摘要建议采用结构化内容：

| 字段 | 内容与来源规则 |
| --- | --- |
| goalReferences | 指向原始目标，不替换用户原文 |
| findings | 已观察证据及对应工具 callId |
| hypotheses | 未确认的推断、当前置信理由 |
| rejectedApproaches | 尝试或排除的方案、原因和适用条件 |
| decisions | 选择理由、前提与证据来源 |
| blockers | 未解决错误、未知事项和需要核实的条件 |
| nextActions | 建议下一步、先决条件和所需证据 |
| evidenceReferences | 相关工具 callId、可见结果片段与文件 revision |

不要再让摘要独立维护一份可覆盖事实的 done 列表。摘要声称“已修改”或“已验证”时，要能关联到事实；关联存在仅证明来源存在，不证明模型结论正确。无法机械验证的解释保留为模型判断。

该结构保护的是“为什么下一步这样做”，不只是文件名和函数名。源代码、错误串和关键数值可以作为原文证据附带，不应依赖自然语言转述恢复精确内容。

## Handler 分工

| 职责 | 提案中的处理 |
| --- | --- |
| ContextHandler | 从固定快照生成上述内容；默认保留完整历史，采用有效摘要时只替换覆盖内完整旧助手/工具批次 |
| PreparationHandler | 继续执行显式选择的有界项目参考；不扩大扫描范围 |
| ContextWindowHandler | 测量完整请求，计算准入，调用内部纯策略选择保留、摘要或拒绝 |
| CompactionHandler | 按合法边界选择分段，执行摘要并校验结构、来源及窗口收益；请求 Runtime 提交采用事实 |
| UsageHandler | 汇总普通推理、摘要及其他已声明模型处理的真实用量；未知不能记零 |
| InferHandler | 执行固定模型能力，不决定上下文策略或改变请求配置 |
| CallHandler | 执行原工具或有界历史读取；不会为取回输出重复旧能力 |
| JournalHandler | 外层执行窗口与结果提交；内部真实请求仍由 Runtime 唯一端口包围 |
| AuthorizationHandler | 验证固定来源、参数和当前授权；摘要不继承或授予新的执行许可 |
| HumanInteractionHandler | 保持人工等待语义，不伪造已执行结果 |
| AuditHandler | 观察耗时与状态；正式通知仍只基于已提交事实 |

ContextWindowHandler 不需要成为新的插件系统。当前实现是普通纯函数 `selectContextStep(profile, metrics)`，按声明式 Profile 选择第一个可执行步骤或返回保留；它不读文件、调用模型、提交日志或访问当前时钟。模型建议若被采用，先作为明确外部输入落事实。Profile 的结构、快照与可追溯记录见 [声明式上下文策略链](context-profile-engine.md)。

## 窗口、触发和保留算法

### 分开三个额度

1. 单次上下文额度：避免请求无法装入模型窗口。
2. 单次生成额度：由明确请求配置及模型能力决定，不为省输入而静默降低任务输出上限。
3. Turn 累计用量：阻止后续请求继续消耗，不撤销已发生的调用。

令 W 为模型窗口，O 为当次已确定生成额度，S 为计数与协议安全余量：

```text
B = W - O - S                         # 完整输入准入额度
T = B - growthReserve                 # 容量触发线
I = measure(fullPreparedRequest)      # 系统、工具、准备、历史、证据全部计入
U = measure(history[coveredMessageCount:])   # 尚未被已采用摘要覆盖的原始历史
G = compactGrowthTokens               # 增长触发量，默认 100_000
```

O 优先使用显式 maxTokens；缺省时必须明确解析模型/宿主的实际输出配置，不能为了计算预留就强行把普通推理改成 4096。无法确定的额度和计数方法应明确说明，不伪称硬保证。

measure 区分精确计数与估算，记录方法与版本。已有 UTF-8 字节估算只能作为后备，不能改名为 tokenizer。误差校准只能使用已有 usage 与可比较的请求事实，不读环境或依赖隐藏可变计数。远程计数若需要 I/O，必须另有显式执行与事实边界，不能藏在同步 measure 中。

作为待评测的起始参数，可设：

```text
growthReserve       = min(16_384, floor(0.15 * B))
recentTarget        = min(20_000, floor(0.25 * B))
compactGrowthTokens = 100_000
```

这些是 Archer 的实验基线，不是论文证明的最优值。growthReserve 与 O 不同，不能重复当作生成额度；小窗口下应按可用空间收缩，必要内容装不下则拒绝。

只按容量线触发时，估算越准确，工作集就越会接近整个窗口：在 1M 窗口上可能一直增长到接近输入额度才开始摘要，单次摘要源也随之变得很大。增长触发量直接约束“尚未被摘要覆盖的原始历史”，与窗口大小解耦：采用摘要后未覆盖范围缩小，体积回落到近期目标附近，形成稳定锯齿；每次摘要处理的源历史也有上限。容量线仍是硬边界，小窗口先触到容量线，大窗口先触到增长线。U 用两次本地计量之差估算，剥离固定前缀、工具声明和协议开销，不引入新的 provider 调用。

### 保留与触发

- `I <= T 且 U <= G`：不因节省 token 自动改写历史，不套用固定 32K 字符软裁剪。
- `I > T 或 U > G`：在没有未完成工具调用的安全边界选择旧前缀，保留近期完整批次，并生成工作交接摘要。
- `I > B`：普通请求不得执行。仅在摘要请求本身可容纳、预算足够时压缩；无法满足则明确拒绝，不能因为调查尚未结束就越过窗口。

近期选择从最新完整批次向前累计 token，至少覆盖最近一次有效用户输入及其尚需配对的交互。recentTarget 是目标，不是强制切在 token 数上的刀口；原生调用和结果必须整组保留。若一个不可拆批次大到超过可用额度，返回明确诊断，不假装有一个总能奏效的裁剪方案。

阶段声明只是模型输入提示，不能证明阶段已完成。默认不因它自动提前删除历史；任务感知触发的收益应单独评测。硬窗口仍是最后准入边界。

### 摘要生成和采用

选择范围固定到当前已提交快照。摘要请求只读取本段原始历史、必要执行事实及上次交接信息；不重新运行工具，不运行无关项目准备。避免只反复摘要上一次摘要而永远不接触原始证据。

摘要输出额度根据源段、模型输出能力和可用窗口显式决定，不固定为 2048。输入也超窗时，按完整批次有界分段，不能无限递归。每个 INFER 的摘要次数仍受明确上限与累计预算约束。

采用前纯校验包括：

- 响应完整、非空、不含工具执行计划，结构符合约定。
- 来源引用存在、属于固定源快照，覆盖连续且不拆配对。
- 不将 failed、unknown 或计划中的调用描述成确定成功；能机械判定的矛盾拒绝采用。
- 在相同计数方法下，完整候选请求比替换前更小，并满足窗口准入。
- 需要继续写入的关键前提、待验证证据未被当作既成事实。

结构、引用和减量检查不是语义正确性证明。只因摘要有格式或由另一个 LLM 打高分，不能标记任务质量通过。无效候选不采用，原始历史仍在；已产生的用量照实计入。请求仍可容纳时允许继续原始视图，超限则明确失败，不重复生成到成功为止。

## 原始证据读取

建议通过现有 Tool Contract 提供一个显式装配的只读能力，示例模型接口为：

```ts
history.read({ callId, offset, maxChars })
```

这是拟议的工具 API，不是已导出的实现。callId 使用模型已经见过的工具调用身份，不给模型暴露 AgentJournal、事件 ID、内部 Effect ID、CapabilityRef、revision 路由或日志文件路径。不增加证据 URI、目录树、另一套注册表或持久化别名索引。

同一 Agent 内实际可读取对象是已有事实中已确认 CALL 的原始模型可见结果；范围必须受限。工具有 resultView 时只开放原本允许给模型的正文，不顺便开放完整 value 中未投影的元数据、凭据或进程信息。分页读取支持返回原始长度、截取范围和明确的历史来源。

Provider 不持有 Runtime 或可写 Journal。为此可在 contracts 定义一个最小进程内只读历史端口，由 Runtime 绑定当前 Agent 并通过 OperationContext 注入；调用方参数不能指定别的 Agent。这个新端口保护的是“取回已确认观察而不重复执行”，现有 FileAccess 无法合理表达内部事实读取。它不提供日志提交、恢复或调度能力，也不修改 Provider 生命周期。

读取本身仍走普通 CALL：固定能力、输入校验、开始提交、结果提交。所有 Agent 仍共享同一 Archer 工具集合；数据隔离来自端口绑定，不是新增工具筛选框架。

文件 Provider 的 read 负责获取当前文件；history.read 负责获取历史观察。两者不可互相替代。历史摘要不得暗示旧源码仍是当前源码，修改文件前仍按实际 revision 重新读取并使用既有 CAS。

检索第一次返回哪些片段可先由模型按 callId 指定。自动语义搜索、训练过的行级裁剪、Repo Map 都不属于基础方案，不自动扫描工作区。

## 事实、提交与恢复

复用现有 inference.requested、inference.responded、inference.request.failed、context.compacted 和外层 Effect 生命周期。

实际采用的 Profile 版本、命中步骤、触发原因与优化前后估算记录在同一推理结果的 contextPlan 中；源快照边界、所用摘要请求、保留范围、证据调用身份、计数方法和额度仍由请求与 context.compacted 事实表达。实际模型消息就是请求事实，不用另一份选择日志替代真实输入。

context.compacted 记录结构化交接、原始覆盖范围和生成请求身份。执行状态参考由源事实确定性派生并随实际请求保存，不引入独立可写“任务状态存储”。来源 revision 不是代码或外部内容一致性的证明。

```text
完整意图与 started 已确认
  → Handler 选择固定历史并构造摘要请求
  → Runtime 提交摘要实际请求
  → InferHandler 调用模型
  → Runtime 提交响应
  → Handler 纯校验
  → Runtime 提交摘要采用事实
  → 重建上下文，重新检查用量与窗口
  → Runtime 提交普通实际请求
  → 调用模型并提交响应
  → 提交外层结果及 Agent 后续决定
```

提交失败或确认未知时隔离，不继续使用未确认摘要。已确认摘要或普通响应继续沿用现有恢复复用规则。历史证据读取绝不触发成功写入的重放；未知副作用仍需原有对账流程，不能通过压缩或取回文本绕过。

摘要失败、断连与输出截断不自动等同可重试的超窗。若后续支持一次超窗恢复，仅响应明确的窗口拒绝，重新提交压缩和重试意图；不能泛化成普通 Provider 自动重试。

## 缓存与研究能力的边界

保持系统规则、工具定义及顺序稳定；动态参考放在稳定部分之后。摘要和普通请求分别记录用量、缓存明细与耗时；实际费用仅在有明确 Provider 价格来源时计算。缓存读写已经包含在输入中，不重复求和。

本提案采用同步、有界压缩。APEC 的异步并行摘要与当前单在途 Effect 的约束冲突，不能把并行请求藏在 Service 中。它的增量分段、稳定摘要前缀思想可在独立评测中比较，但不直接承诺同样的缓存命中率或成本降幅；摘要前缀本身也会持续增长。

不默认添加模型可自主调用的 compact 工具、不部署训练过的裁剪器。声明式 Profile 只声明顺序、参数与条件，不加载实现代码，也不是可执行插件体系；新增步骤类型仍是 Handler 契约变更。AutoCompact 的学习策略和 SWE-Pruner 的训练选择器属于与基线分开验证的实验方案。

## 质量验证设计

验证对象是压缩后的续跑能力，不只是摘要的长度和可读性。评测使用独立离线工作目录和明确构造的仓库状态，不通过生产恢复接口重放外部写入。

### 配对条件

固定同一历史 H、仓库与未提交修改状态 D、解释器/依赖、后续用户请求、模型、推理等级、工具、权限、环境步数和预算规则。两组从独立复制的 D 继续，不共享后续可变文件，不泄漏参考补丁、隐藏测试或压缩边界之后的信息。

源历史在窗口内才运行完整历史对照；超窗任务单独报告可继续性，不能换成另一个更强模型后把质量差异算到压缩策略上。模型随机性需要多次运行和配对统计，不能以一个 seed 下定论。分别报告相同续跑预算下的信息替换效应，以及包含摘要费用的相同总预算下的系统收益；不能把压缩费用造成的少行动轮数全部解释成信息丢失。

| 模式 | 检验内容 |
| --- | --- |
| A：完整历史 | 可容纳窗口内的基准 |
| B：完整历史 + 确定性执行参考 | 分离“事实突出显示”与有损压缩的影响 |
| C：事实参考 + 工作摘要 + 近期原文 | 基础压缩的任务保留能力 |
| D：C + 有界历史证据读取 | 证据可恢复性的价值与额外开销 |
| E：D + 任务相关行级裁剪 | 作为独立实验测量裁剪的额外影响 |

至少包含跨文件修改、失败方案排除、撤销变更、连续测试失败、用户约束冲突、历史与当前源码不同、未知写入和多次压缩。多 Turn 后续任务提前固定，避免只测一次压缩或从不同轨迹自动生成不同要求。

### 指标与准入

首要报告 damage（完整历史成功而候选失败）、rescue（反向改善）、总体完成率及约束违反；不能让救回的任务掩盖损害的任务。小样本先报告计数和置信区间，不能宣称质量等价。

同时记录压缩后首个行动是否使用了交接前提、重复调查及重复写入、正确历史证据取回、错误假设复用、累计真实用量、摘要额外请求、缓存明细、总费用和端到端耗时。重新读取次数上升不必然是坏事，要区分必要的当前状态验证与遗忘造成的重复探索。

工程不变量测试必须保证：原始事实不变、调用配对完整、未知副作用不被改写、跨 Agent 读取拒绝、采用前提交失败不执行、采用确认丢失可恢复且不重复模型调用。质量实验通过不能取代这些测试；这些测试通过也不能证明模型质量。

策略准入采用先质量、再成本的判断：安全与授权不变量零容忍；任务损害容忍度应在观察结果前声明；质量无明确证据时保留已有可比较基线，不因 token 更少就自动启用候选。
