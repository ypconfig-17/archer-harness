# 上下文处理集中在 Handler，实际模型请求独立留痕

## 问题

原始 INFER 意图固定会话历史，但项目参考与历史摘要会改变实际模型输入。只记录原始意图和最终回复，无法完整追踪实际请求；摘要生成如果直接调用模型，会绕过先提交后执行的保证，并漏算用量。

## 决定

Agent 提交完整历史快照与固定能力；Handler 统一构造上下文、管理窗口和累计预算。Runtime 在唯一串行提交边界内记录每个真实模型请求的输入、用途和响应，摘要采用另有 context.compacted 事实。Agent 对这些事实执行同一套线上与回放校验。

一次 INFER 可以串行包含有界的摘要请求及一个普通请求。复用固定 Inference 能力，不新增摘要模型网关、能力注册器或 COMPACT Effect，不创建子 Agent。每个真实请求独立遵守先提交输入再调用、确认响应后才能使用的规则；Runtime 提供提交端口，Handler 不直接操作存储。这个选择允许既有每 Turn 一个在途 Effect 的约束继续成立。

inference.requested 是具体模型调用的意图和开始边界；effect.started 则是整个 INFER 执行窗口的开始。二者保护的范围不同，不能用外层开始事实代替动态生成的摘要输入。requestId 与请求 attempt 由既有事实确定性派生。

确认响应独立于外层完成，使恢复能够复用已经取得的回复。摘要请求成功但采用中断时复用相同输入的响应；摘要采用后直接复用已提交内容。失败或未确认请求的实际用量未知，显式预算不能把它当作零。

## 取舍

日志会额外保存真实请求与模型响应，增加大小与全量回放成本；这是追溯实际输入和避免重复模型请求的代价。摘要不会删除任何原始日志，也不是存储 checkpoint。

保留全部用户和系统消息原文，只将安全边界内的早期助手和工具交互替换成非可信摘要。这避免用户约束只剩模型转述，但不能保证无限会话永不超窗。摘要语义无法用结构校验证明，仍需保留原始事实并明确区分计划、确认结果与未知副作用。

模型窗口与估算经 Inference 的显式可选 measure 方法提供。Contract 增加 optionalMethods 声明：Camp 只绑定声明的方法，可选方法不存在代表不支持；存在但非函数仍拒绝。这样保留 Camp 的声明式接口边界，不暴露整个实现对象，也不为计数另建注册机制。没有 measure 时不承诺窗口检查和自动摘要；Pi 的字符类别估算有安全余量，但不等于精确 tokenizer。

窗口充足时保留原文，不按年龄裁剪工具正文；近期保护依据 token 体积和完整调用批次。普通请求输出配置不因预留被改写；无收益摘要不采用。预算阻止后续请求，不提供费用硬上限。自动摘要至多处理 4 段，摘要输入也必须通过窗口检查；不可拆分超长交互不强行裁剪。Prompt Cache 由 Provider 适配，策略保持固定前缀与顺序，尚无按价格或缓存命中率自动调参的决策器。

日志校验要求 INFER 完成对应已确认的普通请求响应。缺少这些事实的旧格式日志明确隔离，不提供兼容分支或自动迁移，也不删除用户数据。
