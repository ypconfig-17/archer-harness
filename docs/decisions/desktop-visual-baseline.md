# 桌面整体视觉母版

本文件约束桌面界面的整体结构、结果层级与中性表面设计。母版是静态设计示例，不是应用截图；视觉验收需覆盖实际桌面窗口。

## 产品方向

Archer 是以任务为中心的轻量桌面工作空间：对话与执行构成主线，导航负责定位，检查器按需深入。设计必须先确定整体秩序，再确定组件外观。新增主题不能替代空间、内容与交互组织的设计。

四态母版见 [可直接打开的 HTML](../design/desktop-baseline.html)，精确采用 1600×1000 的窗口尺寸以及 44px 应用窄栏、236px 项目导航、弹性任务区与 400px 文件检查器。所有状态共用同一套尺度和色彩；其中内容仅为设计示例，正式界面只能读取实际事实。早期生成图片仅用于方向探索，不作为比例和施工依据。

## 母版尺寸与表面

以 1600px 宽窗口为宽屏基准：应用窄栏 44px、项目导航 236px、文件检查器 400px，检查器打开时中间主区域约 920px。普通文件检查器默认 400px，可在 320–420px 内调整；中间为弹性主区域，正文阅读线 780px。小窗口不能机械保持百分比，必须保留中间可读性，必要时将检查器转为独立视图。

普通检查器默认关闭，记住用户主动开关与宽度；没有选择阅读内容时只呈现条目导航，不占用一个空阅读子栏。Diff、长日志和源码通过明确的宽屏入口进入专业阅读模式，退出恢复原布局。

阅读层白色，导航与辅助层为接近中性的浅表面；正文为中性深灰，辅助文字低一级但满足对比度。强调色用于当前项目提示、焦点、运行中活动及主要动作，会话选中保持中性浅表面。边界是中性细线，行内代码采用低反差底色，不逐个增加强边框。主题机制保留，不增加新主题；中性基线统一由 Token 提供，业务组件不另写配色。

## 四个状态的固定关系

| 状态 | 主要内容 | 必须保持的骨架 |
| --- | --- | --- |
| 主对话 | 用户任务、答复、统一结果摘要、执行详情入口 | 检查器关闭，正文居中，输入区稳定 |
| 运行中 | 实际阶段、连续活动、等待和停止入口 | 不因每次工具调用新增卡片；输入区与主对话同款 |
| 文件检查器打开 | 中间仍是任务与结果，右侧是当前任务的文件变更 | 约 17/58/25 的宽屏层级，不能把四栏压成等权区域 |
| 设置 | 主窗口内工作区、220px 分类导航、800px 正文、返回应用与搜索 | 同一字号与控件体系，复杂配置进入二级详情，表单不逐行套卡片 |

左侧固定小品牌、轻量新对话、与行同底色的搜索、工作区会话组、底部工具；默认只展开当前项目。移除长期抢眼的历史异常大行，以低权重入口保留数量及完整说明。会话选中只用中性浅填充，当前项目只在文件夹图标上提示强调色；项目操作收进行尾浮层菜单，展开、悬停与菜单出现不能移动文字。

## 执行主线

结束后的顺序为：最终答复 → 一处结果摘要 → 按需执行详情。结果摘要组织结束状态、变更入口和真实需关注项；耗时、调用次数、模型及用量收进详情。没有警告就不显示警告占位。上下文整理不在答复中留存：执行中只有一处阶段提示，逐请求事实与估算在「上下文」页签阅读，避免形成竞争入口。

计划不占据执行主线。创建或结构修订只在历史位置保留一行计划事件，显示标题、步骤数与「模型声明」来源，点击查看版本与步骤变化；当前计划另在输入区上方保留一行入口，显示标题、完成数与来源，展开后显示步骤。完整修订在活动视图中阅读。执行摘要保持单行、无卡片底面，只汇总已加载工具调用数、工具确认的文件修改数、需关注数量、已知耗时和片段状态，计划步骤不转写为执行进度。没有实际计划时不生成入口或事件行，也不会因为结束而自行勾选。运行活动只表达模型明确提供的公开反馈和已提交的工具事实，不把原始思考冒充阶段摘要。

会话工作区需区分数据类型：主对话保留公开文本与工具短行；活动页只按已提交事实分组，可按任务、操作或需关注项筛选，原始连续调用与结果可折叠。工具短行不能伪装成执行阶段。分组或连续折叠必须可还原每条记录，保留原始顺序、身份与选择；阶段关系没有事实支持时不生成阶段。

## 验收门槛

四个状态必须在同一窗口尺度和主题下并置检查：主次比例、标题与阅读线、输入区位置、导航密度、普通/宽屏检查器的区别。静态稿不能证明控件交互、窄屏适配或真实运行流程正确。结构实现必须使用 Electron 实机验证；不以构建和单元测试通过代替视觉验收，不继续添加无关装饰和主题。


### 紧凑活动流与历史收敛

公开反馈以开放 Markdown 段落开启一个阅读段落，其后的连续工具在该段落下缩进为紧凑活动组；下一条公开反馈、人工交互或 Turn 结束形成边界。工具行固定 32px 单行，按原事件顺序显示动作、目标、真实状态与已提交的 `durationMs` 耗时，折叠行附带读取 / 修改 / 执行分类计数；已结束调用默认折叠进原生 details（“工具活动 · N 次调用”），未结束、失败和未知调用保持可见。没有公开反馈时只显示中性“工具活动”，不生成“正在分析”等推断标题。工具参数、输出与已提交授权记录通过单次操作的详情阅读；已授权只显示小型辅助标记，不能表示执行成功。

折叠使用 effectId 与首个事实序号作为稳定键，后续事件只追加，不清空或重排用户已展开的记录。只有明确的 Turn 结束事实才可跨边界收敛；断连、暂停、取消请求或 active=false 不推断任务结束。原始思考不进入简版正文，只在活动或独立详情中阅读；临时流明确标记未提交。

用户补充输入、待授权/待回答、失败、非零命令退出码、未知、取消与最终答复保留独立位置；失败与停止只占正文层级，不生成错误卡片。计划创建/结构修订在简版中只保留一行计划事件（标题、步骤数、模型声明），纯进度更新不新增节点，当前计划另由输入区一行入口展示；完整历史仍在活动中可查。历史窗口不跨这些边界，也不把模型推理次数当作业务阶段。当前人工表单按 turnId/effectId 强制留在主流，即使恢复标记已到达也不遮蔽。最终回复只显示一次；原始数据和日志不改写。部分历史的工具调用数标为“仅已加载记录”，不声称完整数量。

键盘使用原生按钮与 details/summary；展开详情与打开检查器分别表达相应语义。长路径单行省略但可在详情完整阅读，状态与计数不被挤出阅读区。所有尺寸与颜色沿用集中 Token，普通行无新卡片或阴影。


### 活动、计划与命令授权的局部层级

普通工具行不使用逐行分割线或成功勾选。目录、搜索、文件和编辑使用对应语义图标，文件类操作优先展示文件名，父目录在同一行降为次级并省略显示，原始完整路径仍在按钮可访问名称、提示和详情中。单次耗时只取已提交的 `durationMs`，放在状态之前，不做前端计时；尝试次数、完整参数与输出仍在单次操作详情中。失败、未知、等待及重试事实不改写。当前运行状态只显示“正在分析…”等短文案，不显示阶段毫秒计时。

计划在摘要展开区内默认展示当前步骤前一项及后续附近步骤，当前项使用轻选中表面。长文本仅在预览中限制两行，完整计划模式显示全部原文；不生成阶段副标题、不改变模型状态或完成数量。展开由摘要自身的原生 details 控制，不叠加浮层、不滚动对话定位；用户手动切换后，声明更新不重新覆盖该选择。

命令授权保留在主对话的当前操作位置，标题为“等待命令授权”，命令使用低反差代码表面。参数明确声明 cwd 时标注“命令目录（参数）”；否则显示当前工作区参考或未加载提示，并在详情明确由宿主解析实际目录，不能从 Shell 字符串或当前工作区推断执行事实。命令文本不改写。操作详情和标准按钮共用紧凑底栏，按钮为“拒绝并结束任务”“允许本次执行”，不增加额外授权范围或自动审批。新人工交互聚焦自身且不强制滚动。


计划展开区随摘要卡片留在文档流，不改变阅读列宽度，也不产生独立浮层坐标系；阶段列表允许纵向增长，展开其余阶段不增加外层尺寸。窄窗口沿用摘要的可用宽度，长文本不得撑出横向滚动条。


### 严格单行活动摘要

工具、思考与公开进度按效果原序穿插，同一次推理的思考与公开进度共用一行入口，详情中分别阅读。活动摘要固定 32px、不换行；文件名、目录、命令和推理预览在可用空间内省略，完整目标仍在可访问名称、提示和详情中。窄窗口不得把目录移到第二行，不再把思考记录集中放到片段末尾。

思考入口使用原生按钮打开独立共享详情弹窗，临时和中断内容明确标注，最终答复不重复进入摘要。授权、人工回答、计划内容和最终回复不受单行摘要约束。历史收敛和异常边界保持不变；这里只改变显示，不修改事实时间或执行策略。

### 活动调用表

活动页以快速定位调用为主要目标，默认以紧凑定列表格聚合已提交 INFER / CALL，选择后在同页读取输入、输出、指标及关联事实。平铺调用降低多层事件折叠的定位成本；全部事件视图保留非调用事实的追溯入口。聚合仅属于展示投影，不增加持久状态、不改变提交与恢复规则。详细交互与验证边界见桌面界面规范的“活动调用检查”。
