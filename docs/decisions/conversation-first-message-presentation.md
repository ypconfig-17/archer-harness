# Conversation First 消息与展示契约

## 目标与边界

主页面以用户输入和 Agent 正文为主线，执行过程嵌入当轮答复。目标视觉为已选定的 Graphite Iris 方案 A：紧凑消息头、单轮一个轻量执行摘要、按需展开、正文与底部输入对齐，Inspector 默认收起。颜色使用现有主题 Token，不以静态示例替代真实组件。

本文约束 renderer 展示投影，不改变 Agent、Runtime、Contract、授权或恢复语义。事件是事实来源，流式文本是临时预览；模型声明、工具结果与任务终态分开表达。

## 当前数据入口

- `lib/conversation.ts` 的 `buildItems` 把已提交 AgentEvent 投影为 user、notice、turn-start、effect、turn-end。
- `EffectEntry` 使用 turnId/effectId 关联创建、开始、暂停、人工请求、重试及终结记录；不按工具名称关联。
- `lib/transcript.ts` 的 `turnPresentations` 汇总时间、调用、推理、模型和用量；`activitySections` 保留人工交互边界。
- `lib/task-insights.ts` 投影计划声明及工具确认的文件修改。
- `PendingInteraction` 使用当前 pending 与终结事实决定是否保留交互入口。

| 模型及累计用量 | 已提交 INFER 结果 | 默认收起 | 部分用量标明不完整，不推断费用 |

## 事件驱动的对话主线

主线由用户输入、Agent 公开反馈、实际执行活动、原位人工交互和最终答复组成。它们按照事实顺序交替发生，不规定“先全部正文、再全部工具、最后人工交互”的模板。每轮有紧凑 Agent 头部，但后续内容片段不因此重复生成消息头。排队输入保留原位置，不凭相邻关系推断 Turn 归属。

一个 Turn 只有一个累计执行摘要，但实际活动可出现多次。摘要汇总调用、当前状态、耗时与异常；它不替代执行活动流，也不能把未来发生的活动搬到较早的正文之前。当前关键调用、工具返回的必要结果及公开反馈保持可见，历史活动紧凑折叠，完整参数与输出在详情阅读。无工具的问答不生成零调用卡，但仍可从活动导航访问事实。

人工交互始终在发生位置展开，完成后原位折叠，问题、选项和回答不丢失。当前授权与未知结果不能被历史收敛吞掉。流式公开文本提交后原位替换、去重，不能因进入摘要而隐藏正在生成的答复。原始内部推理不直接当作公开正文。

## Plan、Turn 与用户任务

用户所说的长任务可以包含多次输入和多个 Turn，但当前会话模型以 Agent 与 Turn 为事实边界；本文不新增可持久化 Task 实体或 Task 调度层。计划有独立 planId/revision，create 与 update 含义不同，阶段状态变化不自动创建新计划。

当前有效 Plan 只在输入区上方显示一行标题和声明步骤进度，点击展开步骤及说明。更新原位替换展示，修订记录保留。简版对话不为计划生成事件行、段落或摘要区块；真正创建另一份计划时，完整活动视图保留轻量历史节点，不堆多个大卡片。历史 Plan 及修订通过完整活动入口阅读；工具活动与 Plan 分离。

跨 Turn 沿用计划只能依据已有声明事实及真实作用域；不得仅凭标题相同、上轮未完成或 UI 需要推断继承。没有跨 Turn 关联事实时显示计划来源轮次，不声称已实现 Task 级计划生命周期。没有计划不补造计划。

## 计数与诊断

逻辑调用按唯一 effectId 计数，INFER 与 CALL 分开统计；重复尝试单列，不把 started 或重放次数计作新增调用。人工交互与计划声明若单列，必须明确计数范围，主摘要和底部详情使用同一口径。历史不完整时标明仅已加载记录。

Turn 主状态和附加诊断独立投影。局部失败后任务完成可显示“已完成 · 存在历史失败调用”；只有明确关联的补偿或验证事实才能写“已处理”，不能因为后续成功就替早期错误销账。结果未知也不能因为 Turn 终结而隐去；有事实依据的未解决事项继续提供详情，但已终结 Turn 不暴露失效提交按钮。

## 状态优先级与可信度

已提交终态优先于过期快照；运行中按正在停止、结果未知、等待授权、等待回答、执行中、推理中区分。历史调用完成不覆盖当前等待状态。需关注是附加信息，不等同整轮失败。计划比例只表示声明中的步骤，不表示耗时或真实完成百分比。

完全访问只改变命令逐条授权策略，不提高操作系统权限。当前任务模式与后续任务默认值分开说明。按钮不能以视觉稿为由发明暂停、拒绝后继续、重试或自动修复能力。

## 布局与交互

正文和输入共享有界宽度；用户消息右对齐，Agent 正文不套大卡片。头部与摘要使用组内间距，不把任务编号、授权模式和“工作记录”分别堆成多行。人工回答历史使用辅助字号；错误与当前授权保持清晰局部边界。

输入框固定底部，发送与停止为稳定动作位置。Inspector 按需开启，长路径省略但可查看原文；长代码可横向滚动。浮层关闭恢复入口焦点，键盘可操作，主题颜色使用 Token。

## 长任务滚动与展开策略

用户停留底部时跟随新增正文和活动；主动上翻后不抢位置，显示回到最新入口。当前活动默认可见，历史内容默认紧凑；用户手动展开优先于自动默认值，不因流式刷新、分页补齐或新活动出现而重置。

组件身份使用稳定事实身份，不使用列表位置作为长期 key。向前加载历史时保持阅读锚点，避免滚动跳跃。人工询问回答后只收敛原节点，不搬入摘要。流式与已提交正文共用稳定位置，提交后不产生双份正文。上下文整理只保留执行中的一处提示，结束后不进入答复。

## 验证标准

行为测试覆盖：普通问答、多调用、失败后继续并完成、任务失败、授权拒绝、等待回答后继续、未知结果、停止请求和终态、历史不完整、同轮摘要唯一性、统一调用计数及流式正文去重。

视觉验收分别提供六类真实或现有演示状态：普通对话、长任务、多 Plan 声明及修订、人工询问穿插、失败后恢复、执行完成。多 Plan 验收区分新建和更新，不制造跨 Turn 继承。逐项检查深浅主题、长文本和代码、权限菜单取消焦点、Inspector 开合、当前活动可见、历史展开保持及滚动跟随。

验收截图与选定方案 A 对比。编译和测试通过不替代视觉验收；文档中的目标行为不构成已实现证明。修改仍限 Renderer 展示投影，不改变 Agent、Runtime、Contract、权限或恢复语义。

## 展示组件映射

组件名称、默认形态与点击去处以 [主对话组件映射](../guides/desktop-conversation-ui.md) 为准。对话只使用六种核心 UI 与两个辅助 UI：

| 组件 | 读取的事实 | 出现位置 | 职责与边界 |
| --- | --- | --- | --- |
| ProgressParagraph（ConversationActivity） | 同一活动片段内的 INFER 公开文本 | 对话简版 | 按公开文本切分阅读段落；只使用已加载事实，不生成阶段标题 |
| ActivityGroup | 段落内连续普通 CALL 与已提交 `durationMs` | 对话简版 | 按 effectId 原序折叠已结束调用，折叠行附带读取 / 修改 / 执行分类计数；运行中、失败与未知保持可见 |
| TurnSummary（ExecutionSummary） | 该 Turn 全部普通 CALL、文件变更构成、Turn 时间 | 对话简版首个活动片段 | 每 Turn 唯一累计摘要；一行入口，展开为累计调用列表，不替代段落 |
| PlanEventRow | 计划创建、修订与快照 | 对话简版与完整活动 | 一行轻量事件；点击查看版本与步骤变化，不铺开步骤列表 |
| ActivePlanBar（CurrentPlan） | 当前活跃 Turn 的最新计划声明 | 输入区上方 | 一行入口（含「当前计划」标签）与折叠步骤；不进入对话段落或摘要 |
| HumanInteractionCard（HumanRecord / PendingInteraction） | ASK_HUMAN 与人工 CALL、暂停与恢复事实 | 原发生位置 | 保持人工交互边界；有选项时使用单选项语义与「确认并继续」，回答后原位折叠成一行，不搬入摘要 |
| AssistantAnswer | Turn 终态中的正式答复 | Turn 结束处 | 标准 Markdown 正文，只显示一次 |
| ActivityDetail（ActivityFlow / InferenceActivity / OperationCard） | 全部已加载 INFER 与 CALL | 完整活动视图与检查器 | 调试阅读；保留推理入口、原始参数与历史计划修订 |

自然段落不是新增领域阶段。只有 INFER 明确公开的文本可作为段落起点；连续工具以已有事件顺序附在它后面，遇到下一条公开反馈、人工交互或终态结束该阅读段落。这个关联只表达时间上的相邻，不声称模型已声明工具归属于某个语义阶段。Plan 标题和 reasoning 均不用于生成段落名。

| 事实与判定 | 主对话组件与默认态 | 展开态 | 详情页 | 缺数据时 |
| --- | --- | --- | --- | --- |

### 段落排版

自然段落之间使用 space-5（24px）建立停顿，正文与工具组之间使用 space-2（8px）。工具组只做左缩进，不增加大卡片、整块底面或明显边框；已结束调用的折叠行与调用短行共用辅助字号。普通反馈为正文，工具名、目标与状态为辅助字号，原始参数与结果在详情中按代码阅读。长命令只在单行内省略，不撑开主阅读宽度。

### 数据契约缺口

以下限制来自已提交的事实结构，不由 Renderer 补齐：

- 没有事实声明“执行阶段”或“段落”实体，也没有把某个 CALL 关联到某条公开反馈的字段。分段只按相邻关系建立，不能声称语义归属。
- 只有 INFER 的公开文本是模型对用户的进度反馈；reasoning 不保证是公开反馈，不能转为段落名或主对话预览。
- 计划步骤状态是模型声明，不是执行事实；计划标题、阶段文本和完成比例都不能当作执行段落或调用成功证据。
- Shell 命令文本只表达执行意图，不能据此推断工作阶段、安全性或文件影响。
- 流式文本是临时预览；提交后由同一 INFER 结果原位替换。分段只使用已加载的已提交事实。
- 历史窗口不完整时，调用数与时间范围标为仅已加载记录，不补造总量或缺失阶段。

缺少公开反馈或稳定分组数据时，界面只渲染中性工具活动组：不编造“正在分析”“正在修复”等阶段标题，也不把命令模式、工具名称或计划步骤升级为段落标题。要让主对话出现更多自然段落，需要 Agent/提示词层让模型输出可公开的进度文本；该能力尚未实现，Renderer 不代为生成或改写。

### 长任务稳定性

累计摘要、段落与折叠组使用 Turn、effectId 和事实序号作为稳定身份。新事件只追加到所在 Turn 的末尾，不重排已阅读的历史；已结束调用按原顺序折叠，运行中、失败与未知调用保持原位置可见。用户手动展开的累计列表与折叠组不被流式刷新或状态更新自动关闭；当前活动始终可见，完整历史按需展开。

## 实现落点

对话简版由 ConversationActivity 将明确公开的 INFER 文本渲染为 ProgressParagraph，后续连续调用进入 ActivityGroup；下一次公开文本、人工交互或计划事件形成边界。ActivityGroup 按原序折叠连续的已结束成功调用，短行显示已提交耗时，失败、未知与运行中调用保留为短行；Shell 行只显示单行命令预览并提供完整提示。reasoning 不生成公开段落或预览标题。TurnSummary 每 Turn 只出现一次，提供累计调用列表、文件变更构成与完整活动入口；组头时间只取已加载 Turn 开始事实。计划由 PlanEventRow 在历史位置保留一行事件，当前计划另由 ActivePlanBar 在输入区展示，完整活动视图保留全部修订。此投影只使用已加载事实，不保证模型提供语义阶段标题。

## 最终答复阅读面

最终答复与此前活动通过段落间距和结果摘要顶部分隔区分，不增加答复卡片或额外封框横线。收尾栏默认只保留终态、真实文件变更、需关注事项和运行详情；操作数量及耗时收入详情，避免重复累计摘要的统计。最终答复不提供复制按钮，正文可直接选择复制。

## 阅读宽度与窄列适配

正文、执行摘要和输入框共享 780px 最大阅读宽度，大窗口居中而不持续拉长行长。主对话列建立 inline-size 容器查询，640px 以下收紧内边距并允许工具栏、摘要和结果操作换行，480px 以下进一步收紧边距。断点依据实际对话列，因此 Inspector 展开也触发适配，而不是只依赖整窗宽度；字体不按窗口比例缩小。长代码仍在自身阅读区横向滚动。

## 组件视觉系统

工具折叠组、轻量 Plan 事件、已回答记录和当前计划入口共享公共 ui-record-surface：单层细边界、同一小圆角、标准控件高度、辅助字阶和一致左右内边距。文件变更卡沿用同一细边界与小圆角，文件行复用 Item 的行结构以及统一的悬停和键盘焦点状态；状态胶囊只用语义色，不新增徽标组件。正文仍使用 type-body，人工交互使用标准标题、表单和公共按钮，不将所有内容降为辅助字号。公共表面定义集中在 surfaces.css，业务只负责布局和语义。

运行时当前工具及待处理人工交互可见，完成调用折叠；公开反馈保留，计划事件一行，已回答一行，文件变更保留入口，累计摘要单轮唯一。当前计划只依活跃轮次显示，结束后隐藏，最终答复完整保留。用户主动展开状态继续由原生 details 保持，不因新增事件强制关闭。

## 公共样式与组件边界

RecordDisclosure 和 RecordRow 位于 primitives/Record.tsx，复用 surfaces.css 的记录表面及全局语义 Token，供工作区和其他页面使用。ActivityGroup 独立负责连续调用阅读，参数为 EffectEntry 与详情回调，不再读取页面私有上下文。ProgressParagraph 独立负责公开正文和预览说明。CurrentPlan 复用公共记录组件。文件变更由 workspace 业务组件 FileChanges 组合 Collapsible、Item、ScrollArea 与 Tooltip；TaskInsights 只把已提交事实投影成文件列表，折叠、滚动和文件跳转都在 FileChanges 内完成。所有组件使用当前设置选择的明暗、界面主题、强调色和文字刻度，不引入单独的对话主题。

## 摘要与计划阅读收口

累计摘要只显示统计与活动导航，不再提供重复的逐工具展开列表；工具明细由原发生位置的 ActivityGroup 承担。计划事件头部显示声明完成数与总数，展开区统一内边距，步骤以固定图标列、弹性正文列、右对齐状态列排列。已完成使用 success，进行中使用 accent-text，未开始使用 muted；状态颜色只表达声明，不证明外部执行结果。修订说明与历史作为次级内容分开阅读。

## 进行中与声明完成的计划视觉

PlanProgress 统一展示标题、来源、步骤比例条与三列步骤列表。部分完成采用主题 Accent，全部步骤声明完成采用 success；始终明确“模型声明”，不把该比例称为真实任务进度。逐步骤耗时没有契约来源，不从整轮时间拆分；计划展示不生成检查结论。执行摘要使用轻强调表面与已有统计，工具明细仍保留原位分组。计划事件默认折叠，用户展开阅读后在同一结构中看到当前声明，历史修订仍可查看。

## 最终实施规范对齐

以用户提供的《Conversation First UI 最终实施规范》为准。计划详情使用外层唯一折叠标题，不再内嵌第二套“计划已完成”标题或重复名称说明。完成态在折叠行显示绿色小图标与完成数；展开面板保留单份计划名称、4px 步骤进度、32px 目标行高和次级修订入口。移除计划主列表内部限高，完整步骤随主阅读区滚动，避免最后步骤被裁切。当前计划全部声明完成后不常驻输入区。进度只表达声明，不伪造步骤耗时。
