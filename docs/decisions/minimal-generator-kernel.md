# 最小 Generator 内核与会话事实恢复

## 背景

Archer 需要将意图表达与外部能力执行分开，同时保留提交先于执行、未知写入不重试和跨重启会话恢复。独立 Effect 状态机与会话执行投影重复保存同一批事实，使调用方需要理解多套推进协议，人工凭证与能力特判也扩大了内核职责。

## 决策

Kernel 只提供 Generator Runner 与 yield* 辅助。Agent 直接折叠唯一 AgentJournal；Runtime 固定组装人工等待、日志与授权包装，通过宿主唯一串行提交端口记录事实。Generator 与命令队列是可丢弃的进程资源。

恢复只承诺重建 Archer Agent 会话及未解决的执行事实，不承诺恢复任意 JavaScript 工作流或代码位置。已提交结果不重做，写入未知保持对账，人工请求恢复等待。日志回放不调用外部能力。

## 取舍

可靠执行仍需要状态与事实，但不需要第二个公共 EffectMachine。包装器不能任意调序、绕过日志或隐藏重试；存储故障必须在能力调用边界之外传播。将可靠性从内核移出不降低其保证，只明确其宿主责任。

任意 Generator 的跨版本确定性重放需要流程身份、意图匹配和代码演进契约，当前范围不承担这部分成本。

## 重新评估条件

只有明确需要任意开发者工作流跨进程精确恢复，或引入并行执行、多进程所有权时，才重新评估工作流标识、检查点或调度机制；不为潜在需求预先增加它们。
