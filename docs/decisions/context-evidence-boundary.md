# 摘要采用与历史证据边界

## 问题与取舍

输入 token 减少只说明容量收益，不能证明任务状态保留。将所有执行事实交给 LLM 重新概括，会使未知副作用、业务失败、文件回执和推理假设混在一起；只检查摘要非空不足以保护继续执行。

当前设计使用三种已有边界：Runtime 从已提交状态绑定只读历史与事实快照；Handler 构造有界事实参考并选择、验证摘要；Contract 定义可序列化交接及只读分页接口。不引入新 Kernel 语义、顶级会话容器、第二套能力注册器或独立提交方。

## 结构化交接

`ContextHandoffSchema` 要求 `version: 2` 和六组内容：`findings`、`hypotheses`、`rejectedApproaches`、`decisions`、`blockers`、`nextActions`。发现、失败方案及决策必须引用原始消息索引和原文引文；决策单列前提，失败方案单列原因。假设不能混同已确认发现。nextActions 为 {action, preconditions, rereadEvidence}，前提与需重读证据分开表达；rereadEvidence 同样校验原始索引、引文与工具分类。前提只是交接数据，不授予权限或证明前提已经成立。

摘要请求携带 `sourceStart`、新增源消息和前次交接。索引相对于 INFER 固定前缀之外的完整原始历史，跨轮追加时保持稳定。引用可以延续前次交接的早期来源，但不得超出本次覆盖范围；引文必须为对应消息的非空白原文子串。工具结果分类若声明，使用 completed / tool-error，必须匹配被引用工具消息的 `isError`，不能将普通消息标为工具执行结果。

交接只描述摘要覆盖的历史范围，不声明全局当前目标或状态。模型仅依据本段和前次交接更新结论；有明确新证据时更新已被推翻的判断、失效前提、已完成行动和已解决阻塞。保留仍有用的失败原因，不以时间较新代替证据强弱。普通模型请求中的摘要参考明确标注原始历史 [0, coveredMessageCount) 范围，近期原文仍可推翻摘要结论。用户原文持续保留，不建立模型提炼的可信约束库。

Handler 与 Agent 回放复用相同纯校验函数。Runtime 先提交真实摘要请求和响应，再提交采用事实。结构、来源、窗口计量一致性和正收益均满足才采用；无效候选不采用，原文能容纳时继续原文，不能容纳则停止。响应与实际用量不会因为拒绝采用而删除。

交接保留 JSON 文本作为已提交摘要内容，不另建可变摘要存储。旧版本结构或自由文本摘要不符合当前协议；回放遇到已采用的旧格式时明确隔离，不做静默转换、删除或模型重写。

## 确定性执行参考

Runtime 只从已提交 CALL 状态提取记录，Handler 在使用摘要的普通请求中附加数据参考。记录区分 pending、completed、business-error、failed、cancelled、unknown；放弃追踪仍为 unknown。显式文件变更回执只保留路径与前后 revision；命令只投影明确记录的退出码，不解释命令文本或 stdout 来猜测成功，也不证明当前磁盘仍为该 revision。

参考优先保留未确认操作，再选择近期收束操作，最多 32 条，记录 JSON 字符合计最多 8192，附遗漏计数。全部未确认操作无法放入参考时停止推理，不能以摘要替代缺失状态。该参考是数据，不能提升权限或覆盖用户指令。它进入完整模型请求并参与窗口计量和请求事实记录。

## 历史证据读取

`HistoryReader` 只有 `read`，由 Runtime 绑定当前 Agent 的已提交结果快照，不暴露 Journal、其他 Agent 或外部执行入口。`historyProvider()` 通过 Camp 提供普通只读 `history.read` 工具；CLI 和 Server 显式装配，SDK 由宿主选择装配。

请求提供 `callId`，可以指定 `turnId`；唯一匹配才读取，歧义明确拒绝。只返回 `modelContent`，未声明专用视图时使用与原工具消息相同的 JSON 正文。隐藏元数据不会通过此端口返回；确定性参考的有限回执字段属于独立、显式的数据投影。失败、取消和未知调用没有可伪造的成功结果正文。只返回捕获快照内的已确认结果，不自动重新执行旧命令。

分页单位是 UTF-16 字符，默认 4096、最多 8192。返回 offset、totalChars、nextOffset 和 isError；超界与负数拒绝，末页没有 nextOffset。页边界不拆代理对；offset 位于代理对中间或 limit 无法容纳下一个字符时拒绝。调用 history.read 自身仍按普通 CALL 提交意图、记录结果并受既有任务执行限制。

## 质量限制

机械校验可以证明引文存在和分类一致，不能证明结论由引文推出，也不能证明用户约束、失败方案或重要前提没有遗漏。执行参考有界，历史读取需要模型主动选择正确证据。结构化输出增加摘要与校验开销，未支持该格式的模型会被拒绝采用，不自动降级到自由文本。

任务质量仍需固定仓库状态下的成对续跑评测，分别报告损害、挽救、约束违反、重复操作、摘要开销和估算误差。工程回归通过不能替代这些实验，也不能据此宣称准确率无损。

## 无可用交接

模型可返回 {"version":2,"kind":"no-handoff","reason":"no-useful-information"}，reason 也可为 insufficient-evidence。这个响应是明确的未采用结果，不是允许替换历史的空摘要。有效交接仍不得全数组为空，不鼓励模型为满足非空约束编造内容。

Handler 返回 CONTEXT_COMPACTION_UNAVAILABLE：原文仍能容纳时保留原文继续；原文超窗时停止。实际摘要响应及用量照常保留，继续原文前也要重新预算准入。context.compacted 不接受 no-handoff，恢复不会把该响应误认成已经替换历史。

## 引用开销报告

构建后可运行 `node scripts/report-handoff.mjs /absolute/path/agent.jsonl`。工具只读取显式文件、验证事件并纯回放，不扫描目录、不修复尾部、不执行工具或调用模型。输出不包含消息原文和引文正文，按请求报告响应字符、引文字符、去重引文字符串字符、引用 JSON 字符、引用数、字符占比、采用情况与实际已报告 token。缺失用量单列，已报告合计不代表缺失部分为零。

所有字符指标均为 UTF-16 长度，不是 tokenizer token 占比。去重统计只按引文字符串，不能将相同文字的不同来源合并成一个证据身份。未采用的合法交接不自动归因为语义失败；报告不推测其拒绝原因，不计算任务损害率，并明确给出 semanticQuality: not-measured。连续压缩工程测试检查索引和原文完整性，不构成模型语义续跑实验。

### 当前确定性压力样本

在 16 条发现重复引用同一消息、结论字段不变的字符压力样本中，报告得到：

| 每条引文长度 | 响应字符数 | 引文字符合计 | 引文字符占比 | 去重引文字符串字符 |
| --- | --- | --- | --- | --- |
| 32 | 1,654 | 512 | 31.0% | 32 |
| 512 | 9,334 | 8,192 | 87.8% | 512 |

这些是 UTF-16 字符指标。样本刻意重复引文，没有代码任务语义；只能说明重复长引文可能挤占交接容量，不能证明真实任务有同样比例，也不能证明缩短引文不损害证据充分性。因此提示词鼓励短而精确的引用，程序不自动截短引文、不合并不同来源身份，暂不增加 evidenceId 索引。

另外，确定性模拟端口连续执行 36 个 Turn，产生并采用 4 次摘要；只读报告与回放的采用数一致，CLI 读取没有改写日志，缺少完整末行时明确拒绝。继承引文被篡改和 no-handoff 被伪造成已采用摘要均在回放时拒绝。端口用量是测试模拟值，不代表真实模型 token 消耗；这些检查仍不测量任务损害率。

## 超大工具结果的请求节选

完整工具结果继续保存在已提交事实和原始历史中。仅当完整模型请求超过输入额度的 85%、Profile 选中节选步骤、模型已装配 history Provider 的 read 能力、当前快照能按 callId 唯一读回正文时，Handler 才为本次请求节选单条占用超过 min(4096, floor(输入额度 × 25%)) 个估算 token 的工具正文。节选保留前部文本和明确的遗漏提示，使用实际模型工具名及 turnId、callId 给出分页读取参数；不更改工具调用参数、签名、配对或 isError，也不暴露隐藏元数据。Unicode 节选不拆代理对。

节选的收益是避免单条可重读结果占满整个模型窗口；代价是本次模型必须按需读取遗漏证据，节选不保证任务语义完整。低于容量线时保留原文。没有历史工具、来源歧义、无法读取或候选结果不足以达到完整输入收益门槛时，不以不可恢复的截断换取放行。最终完整请求仍经过窗口准入，真实请求提交后才调用模型；回放读取原结果，不重跑工具。

工具结果节选采用 85% 容量线与 4096 个估算 token 的单条保留上限，避免接近窗口时反复传输大结果。仍需满足 Profile 条件和完整输入收益门槛；不会自动启用关闭的步骤。仅改变当次模型请求投影，Journal 原文、摘要覆盖与恢复事实不变。验证命令：`pnpm exec vitest run tests/handler/context-policy.test.ts tests/handler/tool-result-window.test.ts tests/handler/context-window.test.ts`，覆盖提前节选、低占用原文、来源与配对、收益及超窗拒绝。
