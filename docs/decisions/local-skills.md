# 本地技能包的来源、格式与资源

Skill 契约和 Runtime 的 `load_<name>` 投影已经存在，但没有任何 Provider 贡献技能。本决策确定个人技能从哪里发现、如何声明、正文与资源如何按需读取，以及设置界面能读到什么。

## 来源

CLI 与 Server 声明两个个人技能根目录：

| 来源标识 | 目录 | 用途 |
| --- | --- | --- |
| `standard` | `~/.agents/skills` | 复用 Agent Skills 生态中的个人技能 |
| `archer` | `<HARNESS_DATA_DIR>/skills` | Archer 自管的数据目录 |

Provider 不扫描工作区，也没有未声明的默认路径。工作区技能需要 per-Agent 工具投影与工作区信任，属于独立架构改动；当前所有 Agent 共用同一 Archer 工具集，因此首版不做。

两个来源内的能力 ID 与 `name` 必须全局唯一。重名、能力 ID 冲突、重复声明同一目录或使用保留能力 ID `read-resource` 时，Provider 构造失败并列出冲突路径，不按扫描顺序覆盖。

## 技能包格式

每个子目录是一个技能包，必须包含 `SKILL.md`。前置元数据声明 `name` 与 `description`，正文即加载内容。目录名作为 Camp 中的本地能力 ID；`name` 遵循 Agent Skills 规范（小写字母开头，只含小写字母、数字和连字符），用于模型工具说明与界面展示。其他前置字段（如 `license`、`allowed-tools`）保留但不解释，避免拒绝生态中已有的合法技能包。

`SKILL.md` 上限为 64 KiB。缺少目录表示没有技能；非法 frontmatter、名称重复、无效目录名或超限文件使 Provider 构造失败，服务启动明确报错，不静默跳过单个包。

## 声明与内容分离

技能实例的能力集合与元数据固定。宿主可以通过 `{ id: 'skills', create: () => skillsProvider(options) }` 接入，再显式调用 `camp.refreshProvider('skills')` 重新发现并发布技能集合。已提交的模型声明不改写；后续准备读取当前集合。GUI 的“刷新”目前只重新读取已注册声明，尚未连接容器刷新。

模型只收到 `load_<name>` 的名称与描述，不把技能全集拼进系统提示。`load` 每次读取最新正文，返回正文和内容 SHA-256 revision；正文变化不需要重启即可生效。能力引用中的 revision 仍然只表示来源身份，不代替内容 revision。

## 资源

技能包可包含 `references/`、`scripts/` 和 `assets/`。这三个目录中的普通文件清单进入技能声明（最多 100 项，超出时标记截断），供界面展示；清单不预读文件内容。

资源读取通过 Provider 贡献的普通 Tool `read-resource`：

- 只允许 `references/` 与 `scripts/` 下的相对路径，拒绝绝对路径、上级目录、反斜杠和空段。
- 读取前用 realpath 固定真实目标并校验仍在技能目录内，符号链接不能逃逸来源边界。
- 单个文件上限 32 KiB，只接受 UTF-8 文本。
- 每次读取都是 `archer.tool@1` 的 CALL，经过 Runtime 的授权、日志与恢复；它不享有额外权限。

脚本不会被自动执行，模型需要运行脚本时仍使用现有 Shell 工具和当前 Turn 的审批。Skill 中声明的 `allowed-tools` 不授予任何权限。`assets/` 只列出，不作为文本预览。

## 设置中的只读预览

设置的能力来源复用同一组注册声明。打开技能详情时，桌面通过只读接口读取正文或单个资源；固定到完整 CapabilityRef，刷新后引用失效会明确提示。宿主读取不产生 Agent Effect，也不写事实。

这改变了“设置不加载 Skill 正文”的旧边界：正文和资源只在用户打开详情或资源时读取，仍不执行技能、不保存配置、不代表授权。

## 影响与限制

设置中的 `skills` 来源会同时显示技能与资源读取工具；空目录时显示 0 项能力。手工 `/` 技能选择、工作区技能、在线市场和远程安装不在当前范围。

## 重新评估条件

需要工作区技能、按 Agent 筛选技能、界面内删除、自动触发能力刷新或手工选择时，先说明对 per-Agent 投影、固定引用、日志恢复和来源信任的影响，再扩展当前模型。

## 设置中的创建与导入

Server 显式装配宿主技能文件管理服务，桌面通过 Client 的管理接口新增技能，不通过 Agent、CALL 或 Camp 注册端口。创建页填写名称、用途和 Markdown 指导；导入页选择并检查单个 SKILL.md。两者复用 Provider 的实际解析器，限制 64 KiB、保留名称和跨根目录的 ID/name 冲突，不覆盖已有技能。导入不携带附属资源，界面明确说明完整资源包需手动放入技能目录。

目标固定为显式装配的 Archer 数据目录，名称校验后才构建路径。宿主串行校验并排他创建目录；新包只写磁盘，不改变当前 Camp、模型工具集合或运行中 Turn。成功回执为 restart-required，页面展示实际保存路径及“待重启加载”，用户自行在任务完成后重启应用。刷新只读注册列表不会激活新技能。未装配文件管理服务的宿主不显示添加操作，管理 POST 明确拒绝。

GET /api/skills/library 返回管理可用性；POST /api/skills/library 接收 content，两者遵循宿主现有鉴权。它不是动态代码安装或技能市场，不执行脚本、不导入工作区代码。验证覆盖鉴权、并发同名只成功一次、原包不覆盖、非法输入不落盘及保存后 Camp 能力不变。
