# 桌面界面的独立归属

## 问题与决策

桌面窗口需要与原生标题栏、菜单、目录选择和持久窗口状态结合；浏览器界面则有独立导航与视口需求。两者共用页面和样式会使布局逐渐依赖平台分支，也使桌面偏好窗口与会话工作区的视觉规则分散。

现有图形界面归属 `apps/desktop/renderer`，桌面应用独立声明 React、Vite、字体与图标依赖，构建并加载自己的界面产物。仓库当前不提供独立 Web 应用，也不保留共享页面包、复制的 Web 实现或兼容启动命令。未来 Web 界面独立实现，仅复用 Client、Contract 与后端能力。

## 架构与执行影响

Electron 主进程只负责桌面能力与后端生命周期；渲染进程通过 Client 请求 Server。Agent 事实、Turn、命令授权、串行提交和恢复规则不变。渲染进程从 preload 获取服务地址；令牌留在主进程，不增加面向浏览器的前端令牌配置。

桌面开发服务器由启动脚本管理，监听成功后才启动 Electron，进程退出后关闭服务器。生产界面输出到 `dist/renderer`，主进程和 preload 输出到 `dist`；两个构建目标不能相互清空。已有桌面本机偏好命名空间与服务标识保持不变。

## 取舍与验证

独立界面允许桌面围绕会话与原生窗口优化，不必为浏览器导航保留平台适配层。代价是未来 Web 的视觉组件需要独立维护，跨端一致性通过协议与各自的行为测试保证，不通过共享页面保证。

设计规则见 [桌面设计系统](../guides/desktop-visual-system.md)。构建、类型检查与测试覆盖桌面产物、原生服务生命周期、窗口恢复和渲染端交互；这些检查不等同于视觉验收。
