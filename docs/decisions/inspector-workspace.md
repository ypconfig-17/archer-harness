# Inspector 信息架构与对象导航

导航归属与文件布局遵循 [会话工作区与文件检查器](conversation-workspace.md)：中间固定「会话 / 活动 / 上下文」三个标签，右侧是工作台。本文关于对象身份、事实来源和未知结果的边界继续适用。

本文只定义当前的对象身份、事实来源和未知结果边界；能力来源只在设置的全局来源页阅读，不提供会话内的请求级来源视图。

## 决策及适用边界

Archer Inspector 是 Agent 工作结果与执行事实检查器：中间的「活动」阅读执行事实，右侧工作台阅读任务确认的文件变更、本地 Git 工作区状态与会话已知字段。检查目的不按后台数据类型分配页面。主对话负责任务与结论，活动页负责定位证据，工作台负责文件与对象阅读。任务回执与磁盘 Git 两类文件来源分开标注，不合并计数或互相补齐。

本决策定义产品结构与对象边界。唯一新增的数据来源是 [工作区 Git 变更视图](workspace-git-view.md) 的只读本地 Git 读取；不授权其他后台数据类型、自行遍历工作区、能力执行或 Runtime 状态。界面验收不能仅凭本文宣称完成。

## 区域职责

| 区域 | 负责内容 | 不承担 |
| --- | --- | --- |
| 主对话 | 用户输入、最终答复、执行摘要、Plan、授权与人工回答 | 重复展示全部诊断数据 |
| 活动页 | 已提交事件的列表、筛选与单条记录阅读 | 请求上下文、能力来源或第二套执行状态 |
| 上下文页 | 已提交 INFER 请求的字符组成（可折叠）、近期与历史输入 Token 趋势、默认收起的条目分组（消息、工具声明、参考与整理事实），按请求快照结构与原始内容两种视图阅读 | 把请求意图当作执行结果、把字符占比标成 Token、把按字符分摊的趋势分段标成模型实际分类用量，或用全局注册信息补齐历史请求 |
| 工作台 | 审阅工具确认的文件变更、本地 Git 未提交改动、活动入口与会话已知字段 | 新的执行管理、请求快照、插件浏览、暂存或提交 |
| 设置 | 全局模型、Provider、权限与偏好配置 | 伪装成某次请求实际拥有的上下文 |

Plan 不生成执行段落：创建与结构修订在对话中只占一行事件，当前声明另在输入区上方保留一行入口；活动页保留完整修订记录。授权与人工回答留在当前阻塞操作位置。最终答复不复制到活动页；模型原始响应仅在事件记录中按需阅读，并明确其请求来源。Token、耗时和推理次数不组成常驻统计面板。

## 固定导航与阅读层级

固定的中间标签只有「会话」「活动」「上下文」，不提供添加、关闭或加号管理。右侧工作台默认列出审阅、工作区、活动与会话概览入口；收起按钮关闭整个工作台，不影响中间标签。

活动页的第二层是当前检查对象：事件列表与单条记录。视图自己的工具栏只承载筛选、范围和返回操作，不重复一级导航。工作台内的审阅只承载任务回执确认的文件列表与差异；工作区只承载本地 Git 的 HEAD 与当前文件差异；活动入口复用同一活动页的已提交事实，会话概览只列已知字段，不推算进度。

窄栏中从列表进入详情时，详情替代列表，并提供明确的返回入口。每次只突出一个主要阅读对象。工作台默认宽度 400px，最小宽度 320px，最大为面板容器 70%，并受会话最小 360px 约束；最大化扩展当前阅读对象，固定导航与对象保持不变。沿用现有主题、字号和控件刻度，不因信息架构调整重做视觉风格。

中间标签保留键盘方向键、Home / End 和标签内容关联；工作台不提供标签导航。进入活动详情时焦点到达详情标题，关闭后回到原记录。Esc 优先关闭最上层浮层；无上层浮层时可退出最大化，不取消任务或更改授权。

## 阅读对象

### 活动：检查执行链路

位于中间「活动」标签，基础层级为「Turn → 推理或能力交互 → 原始事件」。交互依据明确的 turnId、effectId、requestId 和已有请求关联；动作、目标、结果由相应事实投影，不按时间接近、相同工具名或模型思考文本编造执行阶段。

默认显示有意义的交互摘要与需关注项，支持工具与具体来源、模型请求、失败、未知结果及明确人工介入的筛选。缺少声明或无法关联的事件保留独立入口与原始位置，不能为了分组而丢弃。

点击记录打开其参数、结果、错误与原始事件。详情能够关闭并返回原记录位置；原始事件模式是活动内部的诊断阅读方式，不另增一级视图；所有已加载事件及原始 JSON 始终可访问，保留原始编号与顺序。

计数必须先定义范围与单位：工具项数按不同调用身份计数，尝试次数按已提交的 attempt 事实计数，事件条数不能冒充调用次数；开始事实不证明外部副作用已发生。工具失败或命令非零退出码不等于 Turn 失败，未知结果不归为确定失败。人工筛选不把自动对账重试当成人类响应。

### 变更：检查工作成果

位于右侧工作台的审阅入口，默认列出选定 Turn 中工具回执确认的修改文件。每行包含文件名、路径、已知变更类型、可确认的增删量和异常范围；筛选数量必须表达当前范围，例如「显示 3 / 8 个已加载文件」。

点击文件直接选择对应差异对象。窄栏展示变更摘要与范围，并提供进入整窗 Diff 的入口，不强塞完整多行 Diff。宽屏沿用代码阅读与变更路径树结构；该树仅来自变更记录，不表示全部工作区目录。

严格区分本轮工具确认的历史修改、当前磁盘内容和 Git 工作区变更。审阅只承诺第一种；工作区入口只读第二种，并明确标注与 HEAD 比较、不代表任务记录。Shell 输出不能自行转成可靠文件变更清单。原文未知时不计算净增删，不连续片段不拼成完整 Diff；记录未加载完全时不使用无范围限定的“全部”或“完整差异”。工作区读取上限、不可用原因与只读命令见 [工作区 Git 变更视图](workspace-git-view.md)。

### 工作区：检查磁盘 Git 状态

位于右侧工作台的工作区入口。仓库路径只取会话记录的工作区目录，不接受任意路径；只运行固定的只读 Git 命令，不经过 Shell，不执行暂存、提交、还原或外部 diff 驱动。

文件按修改、新增、删除、重命名、复制、未跟踪、冲突与类型变更标注暂存状态。两侧原文可读时才展示行数与差异；二进制、单文件或总量超限、文件数超限与读取失败只报告状态，不传原文、不推算统计。不是仓库、缺少工作区或找不到 Git 时显示明确原因，不伪造空变更。

## 对象驱动的打开规则

对象定位由所属会话、Turn 及事实身份组成。文件还需要变更片段身份；事件记录需要所属事件的原始序号。不得用显示标题、工具别名或当前选中的 Turn 猜测来源。

| 用户动作 | 打开位置 | 保持的对象 |
| --- | --- | --- |
| 点击文件修改数量 | 工作台审阅列表 | 对应 Turn 和已加载范围 |
| 点击变更文件 | 审阅详情，可扩展为整窗 Diff | 路径及明确变更片段 |
| 点击执行摘要的活动入口 | 中间活动标签 | 对应 Turn，不要求先选标签 |
| 手动打开工作台并选择工作区 | 工作区 Git 列表 | 会话记录的工作区与当前磁盘，不关联 Turn |
| 点击活动记录 | 活动页的单条记录详情 | 原始事件序号与范围 |
| 手动打开工作台且无选中对象 | 工作台首页 | 当前会话与已加载范围 |
| 切换中间标签 | 恢复该标签的选择与阅读位置 | 当前会话内的对象与范围 |
| 关闭再打开工作台 | 恢复工作台首页和宽度 | 对象仍有效时恢复原选择 |

后台执行和新事件不自动打开工作台，不切换中间标签或抢焦点。新记录只更新计数，只有用户主动选择才改变正在阅读的对象。

选中对象未加载时显示其身份与未加载提示，并保留返回和现有历史加载入口；不能静默改选最近对象。实际删除、切换会话或对象失效时明确提示并清除无效选择，不把旧索引应用到新记录。会话之间不串用对象定位。

关闭与重开属于本机布局偏好。持久化可保存宽度、工作台打开状态和不含敏感内容的身份，不能复制消息、凭证或整份请求快照到偏好中；加载后通过原事实校验身份。对象选择、返回和整窗布局不进入 Agent 事件日志。

## 原功能归属

| 原入口 | 归属 |
| --- | --- |
| 变更 | 右侧工作台的审阅 |
| 本地 Git 未提交改动 | 右侧工作台的工作区，只读 HEAD 与当前文件 |
| 运行事件 | 中间「活动」，完整事件为其内部阅读层级 |
| 调用详情 | 活动页的单条记录详情 |
| 能力来源 | 设置的全局来源页 |
| 会话概览 | 右侧工作台入口，只列已知字段；不作为中间活动子视图 |
| 加号与标签关闭 | 不进入产品交互 |

## 架构与实现边界

Inspector 以只读事实投影与本机导航为主；工作区入口额外执行固定的只读 Git 命令，但不自行遍历工作区、不新增 Provider 注册、执行调度或事实存储机制。整窗是同一工作台的布局状态，不是新的 Runtime 或 Session。缺少可验证关系时降级为明确的独立记录，不增加推断性持久字段。

工作台只承载审阅、工作区、活动与会话概览入口，能力来源回到设置的全局来源页；活动与工作台之间不共享自动返回栈；对象定位以原始事实和身份校验为准。

## 验收契约

- 中间始终且仅有「会话 / 活动 / 上下文」三个标签，右侧工作台只承载审阅、工作区、活动与会话概览入口；主对话中的活动入口直接定位活动页。
- 工作区只读会话记录目录的本地 Git 状态；不可用、二进制、超限与读取失败不补造内容，也不进入审阅计数。
- 返回列表、切换视图、关闭重开、整窗还原均保留有效身份；跨会话、历史未加载及事件更新不串用旧选择。
- 新事件不自动展开或切换视图；活动页能访问同一批原始事实，筛选与原始记录保留。
- 技能未加载、来源缺失、原文未知和 Token 缺失均不补造。
- 原始事件不因分组、筛选或展示模式消失，状态、计数、修改范围和历史范围符合上面的事实边界。
- 窄栏只突出一个对象，长 Diff 与长输出在整窗阅读；Plan、授权、人工回答和最终结论仍留在主对话。

测试需覆盖对象定位、返回与恢复、未加载及失效状态和原始事实保留。Electron 实机检查交互与布局；按用户要求不做浏览器测试。文档审阅、构建或类型检查不能代替产品架构已经实现的证明。
审阅文件树与正文使用 `@archer/ui` ResizablePanelGroup / ResizablePanel / ResizableHandle，分隔线支持拖动及键盘调整；树列至少 140px、最多占当前审阅区 50%，正文至少 180px。审阅区宽度小于 600px 时默认收起文件树，可通过工具栏显式展开，用户选择优先于默认响应式布局。工作台保存本机像素宽度偏好，恢复后仍由当前容器约束实际宽度，不改变任务事实、文件内容或恢复语义。验证包括宽度偏好保存与恢复测试、桌面构建；实机验收拖动外侧及树列分隔线、缩窄窗口、展开收起树、最大化与键盘调整。



导航与工作台统一使用 `@archer/ui` 的 ResizablePanelGroup、ResizablePanel 和 ResizableHandle，底层由 react-resizable-panels 管理指针、键盘、尺寸约束和实时跟随。左侧不保留自定义 pointermove、动画帧、尺寸预览或临时样式方案。导航展开范围为 260–420px，折叠固定为 56px 图标轨，移动端导航面板为零宽并继续使用 Sidebar 抽屉；展开恢复已保存宽度，不重建会话。Sidebar 在桌面面板中使用普通定位，取消原 fixed 容器与占位的重复宽度控制。

导航与右工作台只在公共组件报告用户调整结束时保存本机宽度，拖动过程不写全局状态；审阅与上下文分栏保持局部布局。导航分栏包装仅负责选择宽度偏好及折叠映射，不实现第二套拖拽。验证运行 UI 和桌面构建、宽度偏好测试；实机需验收左右拖动、键盘调整、折叠后恢复宽度、移动端抽屉与长会话流畅度。
