# Agent 正文由 Streamdown 渲染

## 问题

Agent 回复需要稳定展示标题、列表、表格、脚注、代码、数学公式和图表。正文来自模型，原始 HTML、任意 URL、远程媒体与图表源码都不能视为可信内容；流式生成时未闭合的 Markdown、代码围栏和公式也必须逐块可读，不能反复整体重解析或吞掉后续正文。排版还要与桌面既有字号、间距、明暗主题和强调色一致，不能出现两套互相竞争的正文样式。

## 决策

`apps/desktop/renderer/src/ui/primitives/Markdown.tsx` 是生产正文的唯一渲染入口。Streamdown 负责 Markdown 解析、流式块、代码高亮和交互；`AssistantAnswer` 继续负责标题结构、结果与操作插槽，公开组件接口不变。渲染器不引入第二套 Markdown 解析管线，也不在适配器里隐藏自研解析器。

插件固定为四类：`@streamdown/code` 提供 Shiki 高亮与代码块交互，`@streamdown/math` 提供 KaTeX 公式，`@streamdown/mermaid` 提供图表，`@streamdown/cjk` 修正中文加粗与标点边界。代码主题使用 `createCssVariablesTheme` 生成 `--shiki-*` 变量，明暗模式与强调色由设计 Token 直接驱动。

remark 插件保留 Streamdown 默认集合（GFM、围栏代码元信息），再追加原始 HTML 字面化；直接传入自定义数组会替换默认集合，因此必须显式合并。

流式模式使用 Streamdown 的 `mode`、`isAnimating` 与 `caret`；接收循环即时消费累计正文，每个浏览器绘制帧只提交各 Effect 的最新快照，避免同步外部状态更新阻塞 SSE 消费；不增加逐字播放队列或人为控制输出速度；已提交块由 Streamdown 冻结，只有尾部块继续解析。历史回复与已完成答复使用静态模式，与流式阶段共用同一渲染函数。会话主线通过 `ConversationActivity → PublicFeedback → Markdown` 显式传递 `streaming`：仅未提交且 `phase` 为 `generating` 的临时正文启用；中断、收束与正式结果使用静态模式。临时预览不写入事实，不参与执行恢复。验证使用 `execution-timeline.test.ts` 与 `markdown.test.ts` 覆盖阶段切换、渲染模式和增量正文即时可见。

排版以 shadcn 官方 `typeset.css` 作为块级基线：容器变量映射到 Archer 字号、行高、节奏、字体与语义颜色。Streamdown 官方组件带 Tailwind 工具类，工具类层优先决定标题、列表、表格、代码块和链接的外观；typeset 负责没有显式类名的元素、块间距与引用排版。`markdown.css` 从全局样式入口 `index.css` 引入：`@source` 只在 Tailwind 编译入口生效，组件内的 CSS 导入不会生成 Streamdown 所需的工具类。

表格外壳在桥接层与 typeset 对齐，不改动官方结构：Streamdown 默认给出「灰底卡片 + 白色内层 + 表头底色」三层表面，工具栏常驻一行，而 typeset 按表格直接位于正文流来编排，两者叠加会在表头上方留下一条外边距空白。现在外壳透明无边框，块间距由外壳的流边距统一承担，表头去掉底色；复制、下载与全屏工具栏在悬停或键盘聚焦时浮于表格右上角，不再永久抬高表格。单元格排版与全部交互仍是 Streamdown 官方实现，全屏对话框由 Streamdown 挂到 body，不受这组规则影响。

安全边界由官方能力加最小适配组成：

- 原始 HTML 在语法树阶段改写为文本节点，只作为字面内容显示，不生成可执行标签，也不依赖“消毒后仍保留 HTML”的宽松模式。
- 链接只接受绝对 HTTP(S)，其余协议不生成 `href`；关闭链接确认弹层，保留点击直接打开与 `noopener noreferrer`。
- 远程图片只接受绝对 HTTPS；`SafeImage` 在用户点击“加载图片”前不创建 `img`，失败可重试，`data:` 与其他协议显示为不可用。
- KaTeX 保持渲染器默认安全选项（`trust` 关闭，`\href`、`\htmlClass` 等不可信命令不会执行）；Mermaid 固定 `securityLevel: 'strict'`。
- 不新增自研 Markdown 解析逻辑；安全适配只处理语法树节点改写与 URL 过滤。

Mermaid 主题跟随桌面明暗设置：渲染器从 `document.documentElement.dataset.appearance` 读取外观，映射为 `theme: 'dark' | 'default'`，避免深色界面出现白底图表。Streamdown 按块缓存已渲染结果，仅更换配置对象不会重绘旧块，因此切换外观时以主题作为正文根节点的 `key` 重建整棵正文，使已有图表与界面一致；普通流式更新不改变该 key，不打断已冻结的块。服务端渲染没有 `document` 时回落浅色主题。

模型常用的反斜杠公式定界符 `\(...\)` 与 `\[...\]` 在解析前归一化为 `$...$` 与 `$$...$$`。CommonMark 会把反斜杠定界符解析成转义字符，语法树阶段已无法识别，因此这一步只能作用于原文；围栏代码块与行内代码保持原样，未闭合定界符也不提前改写。

Markdown 仍是字符串消息的展示投影，不是能力、Effect 或事实协议。附件不使用 Markdown URL 冒充；未来需要附件时必须用可序列化的稳定资源身份表达，并单独说明提交、恢复、权限和资源生命周期。

## 边界

- 只有 Agent 正文入口使用 Markdown：最终答复、流式进度预览、历史回复，以及技能详情等明确展示 Markdown 的页面。
- 纯文本、日志、Shell 输出、Diff 与代码编辑器视图保持原有纯文本或专用渲染，不强行走 Markdown。
- 正文排版样式是全局样式的一部分，不由消息组件各自定义；消息结构、操作栏与事件语义仍归 `AssistantAnswer` 和会话投影。

## 取舍

采用官方渲染与交互意味着代码块自带下载、复制与全屏控件，表格带复制、下载与全屏入口，控件文案统一为中文；这些行为由上游维护，不再由项目逐项实现。表格外壳的视觉收敛只发生在桥接层，官方结构与操作不变。typeset 与 Streamdown 工具类分层后，组件自身样式优先，typeset 只补足未覆盖的排版，代价是需要理解两层职责边界，不能把 typeset 当作万能覆盖层。

Mermaid 图表在滚动进入视口后才懒加载渲染，长对话中未读到的图表不会提前消耗资源；代价是自动化环境或隐藏页面无法立即看到图表，需要真实可见窗口。Mermaid 不再保留自研的源码行数与字符数上限，安全依赖官方严格模式与渲染器自身限制。

代码高亮的语言包与 Mermaid 渲染器按需加载，首屏只承担基础解析、排版与已用到的插件；代价是首次出现新语言代码或图表时有短暂加载。原始 HTML 严格字面化会牺牲部分 Markdown 扩展能力，但保持确定的安全边界；远程图片默认不加载会增加一次用户操作，但避免回复在未经确认时向第三方发起请求。

## 阶段性正文

模型在复杂任务开始、重要发现、实质阶段成果、阻碍或方向变化时，用简短正文主动沟通；普通读取、搜索和工具执行不要求逐次说明，也不重复计划或展示内部思考。阶段正文直接使用推理结果的 `content`，不增加消息协议、额外总结推理或 UI 推断。

当前执行协议中，无工具调用的正文会进入结束路径。任务仍需工具执行时，有价值的阶段正文必须与必要工具调用在同一次响应中返回。主区通过 `ProgressParagraph` 按原发生顺序展示非最终正文，最终答复单独展示；已提交结果与消息事实保留正文，临时流不冒充已提交事实。

验证覆盖正文与工具调用并存时继续执行、正文进入消息历史、后续正文作为最终答复，以及现有主区阶段正文顺序和最终答复去重。真实模型是否稳定产生适量沟通需通过实际任务观察，确定性测试不证明提示词遵循率。

## 正文字号与验证

Streamdown 的标题与行内代码通过 `data-streamdown` 语义属性在桥接层映射到集中式 Token，避免固定 Tailwind 字号越过桌面偏好。默认一级标题 24px、二级标题 18px、三级至六级标题 14px，使用既有字重与间距保持层级；行内代码 12px。字号随小 / 默认 / 大偏好变化，代码块及工具栏不受这组规则影响。验收需检查普通正文、标题、表格内代码和加粗代码的阅读比例。

正文通过 Archer 字号偏好统一选择小 13px、默认 14px、大 16px。桥接层在小于 48rem 的视口通过 `--typeset-size` 抵消官方 typeset 的 1.125 倍放大，官方样式文件保持完整。窗口宽度不再改变正文字号，标题和代码保留既有相对比例，行高与段落间距保持既有规则。

验证时在 48rem 断点两侧分别检查三档字号，正文计算字号应始终为 13 / 14 / 16px；检查标题、列表和行内代码仍保持相对层级。桌面生产构建用于确认媒体查询与变量计算可正常编译。

## 重新评估条件

需要可信 HTML、交互图表、内嵌业务组件、附件或本地资源预览时，先明确输入信任级别、URL 与内容消毒、事实恢复和资源所有权，再扩展对应协议或组件。不得通过放宽全局 HTML、Mermaid 安全等级或 URL 规则绕过这些边界；也不得为兼容旧渲染器重新引入第二套 Markdown 解析。

流式进度只用于临时预览，正式答复以已提交事实为准；时序验证需区分 Provider、传输、Renderer 接收与 DOM 提交。
