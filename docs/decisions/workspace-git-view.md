# 工作区 Git 变更视图

## 决策

右侧工作台新增「工作区」阅读对象，只读会话所记录工作区目录的本地 Git 未提交改动，并明确标注为「与 HEAD 比较，不代表任务记录」。它描述磁盘当前状态，不与审阅、活动事实或工具回执共用来源。

工作台首页由审阅、工作区、活动与会话概览四项组成。审阅回答「本轮工具回执确认改了什么」，工作区回答「这个仓库现在相对 HEAD 有什么未提交改动」。两者可以指向同一路径，但计数、增删量与内容不得合并、互相补齐或推断对方。

## 与审阅的边界

| 对象 | 来源 | 语义 |
| --- | --- | --- |
| 审阅 | 已提交的工具回执 `fileChange` | 某个 Turn 的历史修改，原文可能未知 |
| 工作区 | Git HEAD 与当前文件、`git status` | 当前磁盘上尚未提交的状态 |

工作区视图不执行暂存、提交、还原、checkout、打补丁或外部 diff 驱动，也不写入任何日志。Shell 输出仍不能自行转成可靠的文件变更清单。审阅侧的原文未知、片段不连续与历史未加载规则保持不变。

## 服务端读取

路由为 `GET /api/agents/:agentId/workspace/git-changes`。仓库路径只取会话状态中的 `workspace.cwd`，不接受请求参数指定目录；没有工作区时不猜测默认目录。

只运行固定的只读 Git 命令，并以 `execFile` 直接执行，不经过 Shell：

- `git rev-parse --show-toplevel`
- `git branch --show-current`
- `git rev-parse --verify --quiet HEAD`
- `git status --porcelain=v1 -z --untracked-files=normal`
- `git cat-file -s` 与 `git cat-file blob`

每次调用固定 `-C` 目录与 `--no-pager`，超时 10 秒，输出缓冲上限 8 MiB。两侧内容先确认 HEAD 是否存在：尚无提交时旧侧为空；修改、重命名与复制读取 HEAD 旧路径和当前文件；删除只读 HEAD；新增与未跟踪的旧侧为空字符串，读取失败则缺省，不用空字符串冒充未知。

读取上限保证响应有界：前 8 KiB 含 NUL 视为二进制；单文件超过 256 KiB、单次原文总量超过 2 MiB 或文件数超过 200 时，只报告 `binary`、`truncated` 或 `omitted`，不传原文，也不推算行数。工作区路径解析后必须位于仓库根内；符号链接只读链接目标文本，不跟随到仓库外。

缺少工作区、不是 Git 仓库、找不到 `git` 与读取失败分别返回 `no-workspace`、`not-a-repository`、`git-unavailable`、`read-failed` 及原因，不伪造空变更。

## 界面

入口为工作台首页的「打开工作区」，标记「本地 Git」。选中后与审阅共用左侧文件树、右侧阅读区的同一结构，树可收起为窄栏留出正文宽度；工具栏显示分支、文件数与未列出数量，并提供刷新。

阅读区显示状态（已修改、新增、已删除、重命名、复制、未跟踪、冲突、类型变更）、暂存与未暂存标记、已知增删量，以及「差异 / 源码」切换。差异复用 `@archer/ui` 的 `HistoricalDiff`，审阅与工作区使用同一实现；只有两侧原文都可读且未超限时才计算行数，否则显示「行数未知」。二进制、超限、缺侧和删除分别使用明确空态，不使用示例内容。

后台执行、新事件或切回工作台首页都不会自动打开工作区视图，也不会改变任务事实。

## 影响与验证

本决策只增加服务端的只读 Git 读取、一个 Client 方法与一个工作台视图；不改变 Turn、Runtime、授权、提交或恢复，不新增事实类型，也不支持暂存与提交。读取超时或失败不产生任务事实。

自动检查位于 `tests/archer/workspace-git.test.ts` 与 `tests/desktop/renderer/workbench.test.ts`：覆盖 `-z` 状态解析、暂存/未暂存/未跟踪/重命名、二进制、缺少工作区、非仓库与 HTTP 路由，以及工作区视图的标题与文件阅读布局。Electron 实机仍需在真实存在未提交改动的仓库中核对分支、文件树与差异；没有真实改动时不能用示例内容冒充验收。
