# Runtime 执行机制

Runtime 是 Archer 内部的 Agent 提交与执行机制，不是额外的顶级宿主。

## 串行边界

SessionRuntime 的锁覆盖输入接收、幂等检查、队列消费、纯决策、日志提交和状态读取。预备 Prompt 在锁外编译，锁内捕获版本与显式快照，提交前重验版本；过期结果重新准备。取消、移除或停止会使旧准备失效。

AgentJournal.append 接受 expectedSeq 与草稿，由唯一写入方赋值信封、Agent 序号和 Turn 子序列序号。提交确认后更新内存状态，再通知订阅者并执行命令。提交失败或确认丢失隔离 Agent，不基于未确认状态继续运行。JSONL 的提交锁、已确认前缀摘要缓存、外部修改边界及遗留锁处理见 [Journal 追加校验与缓存边界](../decisions/journal-append-validation.md)。

## 分发

Runtime 使用 `@archer/handler` 的固定执行管线，提供已解析能力、准备调用和唯一串行提交端口。Handler 包不直接访问 Camp、AgentJournal 或会话锁，不承担恢复与调度。

1. 查找已提交且可执行的 Effect，拒绝重复在途执行。
2. 用已提交 CapabilityRef 从 Camp 解析原始实现；不匹配则 blocked。
3. 校验输入与命令审批，在锁内提交必要等待事实。
4. 固定管线提交 started，重验配置与取消状态，然后调用接口。
5. 结果重新进入同一锁，纯决策生成收束和后续事实，同批提交后继续执行。

CALL 解析 Tool.invoke 或 Skill.load；技能适配仅存在于 Runtime，不要求 Skill 实现 Tool。INFER 使用固定 Inference.infer。Journal 由 Context 解析后直接提供提交端口，绝不通过 CALL 自我记录。

Archer 生命周期借用保护共享 Camp，CALL 额外持有本次借用。停止等待实际任务和执行收束后才释放借用与共享资源。关闭预算不改变执行结果分类。

## 准备与模型投影

compileModelTools 读取 Tool 与 Skill 声明，产生工具定义和内部目标映射，没有外部 I/O。全体 Agent 共用 Archer 的工具集合。单个投影超过 256 项或名称冲突明确拒绝，宿主需收窄 Provider 组成。

Archer.preparations 是明确选择，不自动触发所有 prepare 契约。按元数据 order 再按稳定引用排序，输入与引用固定到首次 INFER。准备只获得只读文件端口和本次推理快照；返回 JSON 并受单项 64 KiB、总计 256 KiB 限制。它是可信 Provider 接口，只读端口不能限制实现自行执行 Node I/O。

## 恢复

启动时从 JSONL 全量回放，不请求模型重建历史。未知写入、人工等待、取消请求和排队输入保留明确事实。已提交成功操作不重新执行；started CALL 转入对账，started INFER 按执行契约可安全重试；已有确认的普通模型响应时直接复用，不再次请求。摘要响应和采用事实分别恢复，实际请求及摘要用量不因重启清零。来源缺失或变化不能按名称替换实现。

日志损坏或格式不兼容只隔离该会话并返回诊断，数据文件不自动删除或修复。诊断包含会话 ID、日志行号与未通过协议校验的字段；读取或操作被隔离的会话返回恢复错误，不作为会话不存在处理，也不能复用该 ID 创建会话。进程内锁与句柄均可丢弃；Journal 提交锁文件不自动抢占，异常退出或未知提交后的遗留锁需要显式核查。该锁只保护协作写入者的一次存储提交，系统不提供跨 Archer 实例的同 Agent 分布式调度。

## 项目参考

CLI 与 Server 显式装配 projectContextProvider 并选择其准备引用，SDK 仍由宿主选择 preparations。准备只读取工作目录根部 AGENTS.md、README.md、package.json 和有限根目录索引，不导入或执行代码，也不递归扫描源码。单文件内容按 JSON 编码后的 UTF-8 限制为 16 KiB，根索引最多 64 项且最多 4 KiB，结果最多 56 KiB；省略内容和读取失败明确返回。

单文档预算保证根约定与 README 通常全文进入本次参考；AGENTS.md 自身保持在 16 KiB 内，新增细节写入 docs 并在其中链接。总预算等于三份文档上限加 8 KiB 索引与告警余量，并低于 Handler 单次准备结果的 64 KiB 上限，因此不改变推理侧准入边界。参考是每次 INFER 的固定前缀成本：完整注入两份根文档约 1 万 token，内容稳定时可命中模型前缀缓存，编辑根文档后缓存重新建立。

准备在每次 INFER 执行时重新读取，以反映本轮实际观察；来源 revision 与内容保存在结果事实中。参考插入固定前缀之后、会话历史之前，不能替代当前请求或拆开工具调用配对。项目文件作为参考数据，不提升为系统消息，也不授予权限。

### 会话移除与异常日志管理

正常会话由 Runtime 在串行边界内提交 `agent.removed`，不删除已提交日志或工作区文件。
桌面端的侧栏、会话页和会话管理共用确认与成功清理流程，不在列表里预先禁用删除；是否可删除以及拒绝原因由 Runtime 返回。
执行中或取消中的 Turn 以及排队输入仍拒绝删除；仅有等待人工确认或未知结果对账的 Turn 时可以直接移除，删除只提交 `agent.removed`，不补写 Turn 收束、不重试未知操作，日志仍保留该 Turn 的未完成事实。
停止请求不代表任务已结束，最终可删除性始终由 Runtime 判定。删除当前会话回到新对话页，删除其他会话不改变当前导航。
`tests/archer/session-removal.test.ts` 验证等待人工确认与重启后等待对账的会话可直接删除、删除后旧凭证失效且不补写 `turn.failed`，并验证执行中与排队输入仍拒绝删除。

启动恢复校验失败的日志无法可靠折叠，不能通过补造 `agent.removed` 来清理。
Server 针对本次启动报告的失败标识保存原因，提供受管理令牌保护的诊断、原始日志导出和移出加载范围接口。
移出操作将 `agents/<agentId>.jsonl` 原文件移动到 `isolated-agents` 下独立目录，避免覆盖既有记录；不解析、改写日志或重试外部副作用。
移动成功后才移除诊断并更新健康检查计数，失败保留处理入口。批量操作逐条提交，已成功的记录不会因后续失败回滚。

这是入口对自己装配的文件存储执行的管理操作，不扩展 Camp 能力机制、Agent Effect 或 Journal 提交协议。
只允许处理启动时已确认恢复失败的记录；正常会话不能通过这个接口绕过 Runtime 删除。
隔离文件保留供人工核查未知执行结果，不提供自动恢复或永久销毁入口。当前进程仍拒绝复用这些失败会话的 ID。
验证覆盖接口鉴权、原始记录保留、移动失败、非法标识与非失败会话拒绝、健康计数刷新及 Journal 启动枚举。

## 计划声明的提交边界

计划继续使用普通 CALL 和结果元数据，协议与取舍见 [计划声明与连续执行流](../decisions/task-plan-declarations.md)。Runtime 不管理独立的 Plan 生命周期或 Task / Run 状态，Kernel 不认识计划。Provider 从已提交历史重建本轮声明，以 planId 和 expectedRevision 校验创建、修订及顺序切换，不能保存独立可变进度。

Handler 为 Tool.invoke 的 OperationContext 提供当前调用的 turnId 与固定 CapabilityRef。已有 HistoryReader 增加精确 Turn、精确来源的只读分页 list，单页最多 128 项；read 仍提供有界结果正文。只列举成功收束且有模型调用身份的 CALL，不包含失败、未知或尚未提交的执行。来源版本不同不能借用旧结果推进新计划版本。该端口不暴露 Journal、写入或执行能力。

历史快照和下一份声明的提交仍服从同 Agent 串行执行及每 Turn 单在途 Effect 不变量。结果提交失败或未知时沿用隔离规则；恢复不重放已成功计划调用。普通人工回答恢复同一 Turn，计划版本继续来自原事实；后续新 Turn 不自动继承当前计划。GUI 的输入区计划入口、分段工作记录与活动视图的修订记录仅投影事实，不承担授权、版本仲裁或调度。
