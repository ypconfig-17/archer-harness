# Agent 会话与 Turn

一个 Agent 对应一个持续会话，持久化身份、指令、推理默认值、工作环境、消息、输入队列和执行事实。一个输入产生一个 Turn；每个 Agent 最多一个活跃 Turn，每个 Turn 同时最多一个在途 Effect。

## 决策与事实

Agent 包只执行纯折叠与策略。时间由 Runtime 注入，输入和执行标识由确定性规则生成。决策返回事件草稿与命令；Runtime 提交后才分发命令。回放和实时决策共用 foldAgentDraft。

Agent 日志保存会话事实和 Turn 事实。TurnEvent 是同一日志的子序列，拥有自己的连续 turnSeq，不单独落盘。创建事实包含 `capabilityFormat: 'provider'`，调用事实使用固定 CapabilityRef。格式或事实不满足当前协议时明确拒绝，不补造来源身份。

`send` 提交接受事实后返回 TurnRef；`prompt` 等待 Turn 收束。requestId 对同内容和配置幂等，不同声明冲突。followUp 在活跃 Turn 后排队；steer 在既定边界加入当前 Turn；abort 提交取消请求并暂停队列，不宣称能力已经停止。

## 模型输入

每个 Turn 固定系统规则、工作环境前缀、工具映射和准备安排。工具来自 Runtime 对 Camp 的投影：Tool 变为原生函数，Skill 变为按需加载函数。内部来源引用只进入事实；推理适配器只发送 name、description 和 parameters。

创建会话时将完整上下文 Profile 写入 `agent.created.inference`，显式配置优先，否则固定内置均衡模板。任务可显式覆盖该配置，省略时继承创建事实。Agent 的首个 INFER 固定实际 Profile，后续 INFER 沿用，不从运行时代码补默认值。

Agent 的 INFER 意图固定完整历史、前缀、工具、配置和准备引用。ContextHandler 默认保留历史消息原文，仅按完整请求窗口策略安排有界摘要；已采用摘要可替换早期完整助手/工具交互，用户和系统消息保留原文。inference.requested 保存实际消息、工具和投影统计；完整会话与执行结果不变。摘要由 context.compacted 绑定已确认响应与覆盖范围，回放不调用模型。

Turn 的 tokenBudget 由 UsageHandler 按本 Turn 的真实模型请求事实累计输入与输出，包含摘要请求，缓存不重复相加；外层 INFER 完成不重复计费。每次模型调用前达到预算则停止，已发请求缺少用量、失败或未确认时显式预算拒绝继续。已计划工具与最终回复保留既有语义，单次请求仍可越过累计预算，因此不是费用硬上限。恢复不重置用量。

推理用量保留 promptTokens、completionTokens，以及可选的 cacheReadTokens、cacheWriteTokens。缓存字段是输入的组成部分，不再加到合计；缺少字段表示明细未知。pi-ai 的全零用量无法区分服务未返回统计与真实零值，适配器保守地视为未知，不作为零消耗事实。界面区分累计用量与最近一次输入，缓存命中数不等同于计费金额。

默认不进行历史工具正文的字符裁剪。支持 Inference.measure 的 Provider 在参考准备后检查完整请求窗口，并可触发有界摘要；估算不是精确 tokenizer，不能保证模型服务永远接受。未实现 measure 的 Provider 保留完整历史，不提供窗口检查或自动摘要。职责和算法见 [Handler 设计](handlers.md)。

模型工具名必须存在于本次已提交映射。普通工具使用 `Provider名_能力名`，技能使用 `load_技能名`；名称中的非 ASCII 字母、数字或下划线字符替换为下划线，并限制为 64 字符，不携带引用哈希。规范化或截断造成重名时明确拒绝，不覆盖、不添加隐式别名。名称只负责模型选择，完整 CapabilityRef 仍固定在映射、调用事实与恢复校验中。命名与冲突行为通过 `tests/runtime/model-tools.test.ts` 验证。Runtime 解析引用并调用实际接口。非对象输入通过原生对象包装，在执行前解包和校验。工具调用消息与结果按 ID 配对，未知名称或非法批次形成模型可见错误，不执行猜测目标。

Skill.load 返回正文与可选内容 revision。模型主动加载会生成 CALL，结果和工具消息进入会话事实；宿主直接读取 Skill 不自动产生 Agent Effect。技能资源读取由 Provider 的普通 Tool 进入 CALL，正文加载与资源读取都不扩大权限。

推理前准备必须由 Archer 显式选择。安排和输入固定在 INFER；执行结果进入该次结果事实，只作为本次推理的参考消息，不修改长期消息历史。恢复读取原安排，不能重新选择最新配置。

## 任务阶段

跨模块架构分析、故障调查和多步骤代码修改由模型在主要工作前通过普通计划工具声明简短阶段，阶段目标和解释使用用户语言。声明后直接继续已授权工作，不另设计划审批模式；顺序工作保持一个进行中阶段，阶段完成即更新，调查路线变化时提交完整列表。简单单步请求不要求阶段。

阶段结果复用 CALL 事实与消息，界面投影最近一轮已提交的阶段声明。阶段状态不证明执行成功；受阻或结果未知不能标记完成。提示词引导模型使用阶段，不构成 Runtime 对阶段使用率或调查质量的强制保证。

## 工作环境与授权

文件目录由创建 Agent 时显式提供，必须是存在的绝对目录。工具从本次执行上下文取得目录与 read/edit 范围；文件路径属于工具参数。

`configureExecution` 使用 expectedRevision 串行修改工作区访问和指定 Turn 的命令授权，产生 execution.configured 或 turn.authorization.changed。开始提交前重验执行配置修订；旧授权不能因异步结果而继续生效。

## 失败、取消与恢复

read 明确失败可收束为 failed；write 或 shell 在调用后无法确认结果时记 unknown，进入 reconcile。人工确认 retry 复用原 Effect 和输入并增加 attempt；abandon 结束追踪，保留未知事实，不撤销操作。

停止期间 Handler 可返回 null，表示结果未知且保留 started。恢复将未决 started 归类：INFER 可以安全重试，CALL 进入对账，已完成写入只折叠结果。缺少原能力时 blocked；提交失败或未知时隔离当前 Agent。

系统不恢复 Generator 栈，不保证任意外部操作 exactly-once。工具正文按显式 resultView 选择，不在入历史前固定截断；完整结果仍落日志。支持窗口测量时检查完整请求并生成有界历史摘要；精确 token 和费用硬保证不在当前范围。

## 结束判断与复核

原生推理端口保留 stop/toolUse/length 停止原因；不具备停止原因信息的本地端口可省略。length 结果保留在推理事实中，Turn 明确失败，不把部分答复写入普通会话，也不执行该结果的工具调用。toolUse 却没有调用明确失败。首次空回复记录观察并允许继续一次，连续两次为空则失败；显式推理步数预算依然生效。

结构有效的工具批次按条处理：未知名称和缺少包装参数等调用独立返回错误，其余合法调用按序执行。重复调用 ID、非对象参数等无法构成合法原生消息的批次整体不执行；模型得到诊断后可修正。两类拒绝反馈均列出本次已提交工具声明的准确函数名称（没有工具时为空列表），不包含内部 CapabilityRef，也不进行别名匹配。模型可据此纠正并继续执行；既有无效批次上限仍约束重复错误。验证使用 `pnpm exec vitest run tests/archer/function-calling.test.ts`，覆盖未知名称反馈与纠正后执行。工具明确失败的反馈保留 outcome、错误码、消息及详情。

默认策略从成功 CALL 的 metadata.fileChange 回执识别文件变更；回执需包含 path 和 revisionAfter。出现变更后，模型首次直接答复时记录 completion.review.requested，并转入一次验证与完成情况复核。候选答复留在推理事实中，复核后的答复才追加为普通助手消息。新的文件变更或其后新的操作错误建立新边界；相同边界不反复提醒，复核标记可由事实回放恢复。

复核要求执行相关、已授权的检查，失败后修复并重新检查，或明确说明无法检查的原因。它不提高 Shell 权限，不自动选择或执行项目脚本，也不把命令退出成功当成整个任务正确的证明。没有变更回执的第三方工具及 Shell 内部改文件不会被自动识别为文件变更。复核不是语义正确性证明，模型仍需对最终说明负责。

## 模型推理等级与协议连续性

InferConfig.reasoning 是任务级显式选择，随创建、排队与 INFER 固定，参与请求幂等签名。界面按具体模型的可用等级显示中文选项，分别保存各模型的本机偏好；重试复用已接受的请求，不读取最新偏好替换原等级。

等级选择优先级是任务选择、模型 defaultReasoning、服务 reasoning，最后自动选择该模型支持的中等级；没有中时优先高，再按可用等级选择。不支持推理的模型仅提供关闭。模型目录决定基础能力，配置 reasoningLevels 只能收窄实际支持范围，不能伪造新等级。原生端口在结果中记录 reasoningLevel，非法选择明确拒绝，不静默降级。

Provider 返回的原始思考文本仍保存在 reasoning；reasoningReplay 只补充原始分块范围、签名和来源，不重复保存正文。Agent 把这些字段追加到实际助手历史，推理适配器仅在 API、服务和模型相同时重建原生思考块。切换模型不回传其他模型的签名；该数据不作为用户指令或系统提示词。

项目架构分析要求跟踪相关执行、状态、持久化和失败路径，并解释主要设计取舍及其代价。回复可以简洁，但调查不能退化为目录盘点；不以固定阅读次数或工具调用数量判定分析质量。


## 文本文件输入

AgentInput 支持文字、图片与文本文件内容块。文本文件 `file` 块保存 `filename`、固定 `text/plain` 与 `text`，正文上限 256 Ki 字符；桌面另以 UTF-8 字节限制 256 KiB，严格解码并拒绝 NUL。单次输入最多四个图片或文件附件。
文件不是路径引用或能力调用，不引入 Effect。接受事实保存完整文本，回放共用 `agentInputMessage` 确定性投影，不重新读取文件、不依赖临时 URL。
标题与显示投影只呈现文件名；模型消息包含文件名与正文的 JSON 编码，作为用户数据，不升级为系统指令。文本进入已有上下文窗口与预算处理，不绕过准入。
二进制附件没有解析协议，必须拒绝。验证覆盖文本/图片组合、非法编码、大小边界与序列化回放的一致性。
