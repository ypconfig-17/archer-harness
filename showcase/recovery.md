# 文件写入恢复验证

假设一次任务要求修改文件。Runtime 先提交调用意图和开始事实，然后执行工具。写入可能已完成，而结果还来不及记下。此时重新发起同一个调用可能再次覆盖文件。

| 重启时从日志读到什么 | 恢复时如何处理 |
| --- | --- |
| 已提交成功结果 | 读取结果并恢复状态，避免再次调用文件工具 |
| 写入已经开始，结果尚未确认 | 保留未知状态，等待检查磁盘上的实际内容后对账 |

测试分别模拟在结果追加前丢失确认，以及结果追加后丢失确认。两种情况下都回放日志并检查文件状态，以验证工具调用没有被重放。 [文件写入恢复测试](../tests/archer/fs-write-recovery.test.ts#L238)

## 从同一批事实得到同一状态

Agent 执行时通过事实草稿更新状态。重启后，从已提交日志回放状态。测试把同一批执行事实分别交给两条路径，再比较会话状态和待对账记录。这样，恢复是否一致可以直接用数据判断。 [状态回放测试](../tests/agent/replay.test.ts#L34)

在仓库根目录可运行：

```bash
pnpm test tests/archer/fs-write-recovery.test.ts tests/agent/replay.test.ts
```
